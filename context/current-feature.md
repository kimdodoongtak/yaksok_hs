# 현재 기능: 001 초대 링크 접근과 방장 등록

## 상태

완료

## 스펙

`context/features/001-invitation-and-host-spec.md`

## 목표

초대 링크를 조회한 사용자가 닉네임·숫자 4자리 PIN으로 명시적으로 방장을 등록하고 약속 설정을 시작할 수 있게 한다. 단순 조회·미리보기로 방장을 만들지 않고 동시 등록에서도 한 명만 선점하도록 한다.

범위는 서버 전용 초대 토큰 발급, 링크 조회, 약속·방장·초기 세션의 원자적 생성, 초안(draft) 만료·정리·나가기와 상태별 안내다. 실제 카카오 연동은 010, 약속 설정은 002, 일반 참여·재인증은 003에서 구현한다. 공개 웹 링크 발급 기능은 추가하지 않는다.

## 수용 기준

- [x] AC-1: 링크 발급은 promise_links만 생성한다. 링크 GET·미리보기는 약속·방장 생성이나 만료 초안 삭제를 일으키지 않는다.
- [x] AC-2: 동일 링크의 동시 방장 등록 2건 중 하나만 약속과 active host를 생성한다. 실패 시 약속·방장·세션의 부분 저장이 없다.
- [x] AC-3: 닉네임은 앞뒤 공백 제거·NFC 정규화 후 눈에 보이는 글자(확장 자소 클러스터) 기준 2~12자이며 이모지를 허용하지 않는다. 중간 공백은 유지하고 길이에 포함한다. 약속 내 중복 판정은 영문 대소문자를 구분하지 않으며 표시 이름의 대소문자는 보존한다. PIN은 숫자 4자리로 검증하고 선행 0을 보존한다. PIN 원문은 저장·로그·응답에 남기지 않는다.
- [x] AC-4: 약속별 난수 세션 토큰을 안전한 HttpOnly 쿠키로 발급하고 DB에는 해시만 저장한다. 세션·참여자·약속 검증 없이 설정 변경을 허용하지 않는다. draft 세션은 방장 등록 시각부터 10분 동안 유지하며 조회·새로고침으로 연장하지 않는다. 설정 완료·모집 시작 시 해당 세션을 응답 마감(voting_deadline_at) 후 7일까지 연장한다. 모집 시작과 연장의 실제 연결 검증은 002에서 수행한다. 세션 기한이 남아 있어도 초대 링크가 만료되면 접근을 허용하지 않는다.
- [x] AC-5: 방장 등록 후 10분 이상이면 draft를 만료로 판정한다. 만료 발견 쓰기와 draft 나가기는 링크→약속 순서로 잠그고 세션→방장→약속을 삭제하며 링크를 보존한다. 만료 직전 설정 완료와 경쟁해도 모집 중 약속은 삭제하지 않는다.
- [x] AC-6: Asia/Seoul 기준 발급 시각에서 달력 3개월 뒤 같은 시각을 링크 만료 시각으로 정한다. 해당 날짜가 없으면 대상 월의 마지막 날로 보정한다. 서버 시각이 만료 시각 이상이면 기존 방장·참여자와 유효 세션도 조회·변경·재인증으로 접근할 수 없고 화면에는 “만료된 약속입니다”만 표시한다. 약속 상세·참여자·결과는 노출하지 않으며 만료를 데이터 물리 삭제로 해석하지 않는다.
- [x] AC-7: 등록 중·선점 실패·잘못된 입력·만료 상태를 표시하고 draft에서 타인의 신규 참여를 막는다. 초안 만료 2분 전 안내와 서버 재판정, 초대 링크 만료 시 “만료된 약속입니다”만 표시되는 상태를 실제 브라우저에서 확인한다.

각 AC의 근거와 확인 방법은 아래 TDD 적용 계획에 대응한다. OPEN 항목이 포함된 AC는 해당 결정 전 완료 처리하지 않는다.
