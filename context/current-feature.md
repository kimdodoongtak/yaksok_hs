## 상태

완료

## 스펙

`context/features/004-availability-spec.md`

## 목표와 범위

인증된 방장·참여자가 약속의 날짜·하루 시간 범위 안에서 가능한 30분 슬롯을 선택하고 제출·재제출한다. 주 이동, 로컬 미제출 선택, 빈 응답 제출, 과거 슬롯 보존, 다른 기기의 수정 충돌과 마감 차단을 포함한다.

타인의 전체 현황·후보·조기 마감 화면은 005, 실제 약속 설정 변경·재조율 실행은 007이다. 004에서는 본인 버전과 settings 변경을 받아 입력을 갱신하는 경계를 준비한다. 반복 적용은 OPEN-08 승인 전 제외, 가능/애매 3단계 선택은 범위 밖이다.

## 수용 기준

- [x] AC-1: 선택은 30분 단위이며 한 슬롯 전체가 날짜·일일 범위 안에 있어야 한다. 종료 23:00의 23:00 시작은 거절하고 종료 24:00의 마지막 날짜 23:30 시작은 허용한다.
- [x] AC-2: 세션 본인의 응답만 collecting·마감 전에 저장한다. 방장도 타인의 선택·제출 상태를 수정할 수 없다. 빈 슬롯 집합 제출도 제출 완료로 기록한다.
- [x] AC-3: 기준 버전이 일치하면 슬롯 최종 집합·제출 시각·버전 +1을 원자적으로 저장한다. 중복 슬롯은 하나만 유지한다. 중간 실패는 전체 롤백한다.
- [x] AC-4: 기준 버전이 다르고 결과가 다르면 아무것도 변경하지 않고 AVAILABILITY_VERSION_CONFLICT와 본인의 최신 버전·슬롯·제출 상태를 반환한다. HTTP 경계에서는 409다. 오래된 버전이라도 최종 데이터·제출 상태가 같으면 성공으로 응답하고 버전을 다시 증가시키지 않는다.
- [x] AC-5: 시작≤현재인 요청 슬롯은 무시하고 이미 저장된 과거 슬롯은 재제출에서 보존한다. 미래 슬롯에는 범위 검증을 적용한다. 시간 경계를 고정해 검증한다.
- [x] AC-6: 폴링에서 본인 버전이 바뀌면 미제출 입력을 폐기하고 서버 값으로 갱신한다. settings 객체 변경도 비교한다. 타인의 응답 변화는 본인 버전만으로 판단하지 않는다.
- [x] AC-7: 잠금을 얻은 시각이 마감 이상이면 저장을 거절하고 collecting 상태를 closed로 확정한다. 마감 상태 저장은 제출 거절 때문에 롤백되지 않는다.
- [x] AC-8: 이미지의 선택·드래그·비활성 상태와 최신 사용자 결정의 화면 배치를 확인한다. 모바일 터치·키보드 선택/해제/제출, 보기 단위 변경, 되돌리기·복구, 이번 주·전체 초기화를 브라우저에서 검증한다. 선택 일수·누적 시간 요약과 오늘 버튼은 사용자 결정으로 제외한다.

- 드래그·탭·키보드·현재 주 초기화를 작업 단위로 되돌리고 복구한다. 새 변경은 복구 이력을 버린다. 제출·서버 상태 갱신 시 두 이력을 비우고 열린 초기화 안내창을 닫는다.
