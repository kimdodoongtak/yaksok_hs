## 사용자와 문제

참여자는 허용된 날짜·시간 안에서 가능한 시간을 선택하고, 마감 전까지 자신의 응답을 안전하게 수정한다.

## 목표와 범위

30분 선택·해제·드래그, 주 이동, 로컬 임시 선택, 제출·재제출·빈 제출, 여러 기기의 충돌 감지. 전체 현황 집계는 005가 담당한다. 가능/애매 3단계는 제외한다.

## 사용자 흐름

본인 서버 슬롯·버전 로딩 → 주 이동·30분 선택 → 제출 → 완료 표시. 네트워크 실패 시 재시도한다. 다른 기기나 설정 변경으로 버전이 바뀌면 로컬 미제출 입력을 폐기하고 최신 서버 선택을 보여주며 안내한다. 마감 뒤에는 입력을 차단하고 결과 경로로 연결한다.

## 수용 기준

- [x] AC-1: 선택은 30분 단위이며 한 슬롯 전체가 날짜·일일 범위 안에 있어야 한다. 종료 23:00의 23:00 시작은 거절하고 종료 24:00의 마지막 날짜 23:30 시작은 허용한다.
- [x] AC-2: 세션 본인의 응답만 collecting·마감 전에 저장한다. 방장도 타인의 선택·제출 상태를 수정할 수 없다. 빈 슬롯 집합 제출도 제출 완료로 기록한다.
- [x] AC-3: 기준 버전이 일치하면 슬롯 최종 집합·제출 시각·버전 +1을 원자적으로 저장한다. 중복 슬롯은 하나만 유지한다. 중간 실패는 전체 롤백한다.
- [x] AC-4: 기준 버전이 다르고 결과가 다르면 아무것도 변경하지 않고 AVAILABILITY_VERSION_CONFLICT와 본인의 최신 버전·슬롯·제출 상태를 반환한다. HTTP 경계에서는 409다. 오래된 버전이라도 최종 데이터·제출 상태가 같으면 성공으로 응답하고 버전을 다시 증가시키지 않는다.
- [x] AC-5: 시작≤현재인 요청 슬롯은 무시하고 이미 저장된 과거 슬롯은 재제출에서 보존한다. 미래 슬롯에는 범위 검증을 적용한다. 시간 경계를 고정해 검증한다.
- [x] AC-6: 폴링에서 본인 버전이 바뀌면 미제출 입력을 폐기하고 서버 값으로 갱신한다. settings 객체 변경도 비교한다. 타인의 응답 변화는 본인 버전만으로 판단하지 않는다.
- [x] AC-7: 잠금을 얻은 시각이 마감 이상이면 저장을 거절하고 collecting 상태를 closed로 확정한다. 마감 상태 저장은 제출 거절 때문에 롤백되지 않는다.
- [x] AC-8: 이미지의 선택·드래그·비활성 상태와 최신 사용자 결정의 화면 배치를 확인한다. 모바일 터치·키보드 선택/해제/제출, 보기 단위 변경, 되돌리기·복구, 이번 주·전체 초기화를 브라우저에서 검증한다. 선택 일수·누적 시간 요약과 오늘 버튼은 사용자 결정으로 제외한다.

각 AC의 근거와 확인 방법은 아래 TDD 적용 계획에 대응한다. OPEN 항목이 포함된 AC는 해당 결정 전 완료 처리하지 않는다.

## 데이터와 인터페이스

participant_available_slots를 도입하고 UNIQUE(participant_id,slot_start_at), FK RESTRICT, 30분 시각 제약을 적용한다. participants의 availability_submitted_at·availability_version을 사용한다. 현재 주·드래그·색상은 저장하지 않는다.

제안 Server Action submitAvailability({inviteToken,baseVersion,slots}), 응답 {version,slots,submittedAt} 또는 도메인 오류. 제출 값은 서버 시각·권한·현재 범위로 정규화한다. 중복 재시도 비교와 과거 슬롯 보존의 처리 순서는 명세 예제로 고정한다. 서버 상태 조회는 005의 조회 경계를 공유하며 004 단계에서는 본인·설정 정보로 시작한다.

공통 잠금·서버 시각·오류 계약·DB 테스트 기준은 [분해 계획](../spec-plan.md)의 공통 구현·검증 계약을 따른다. 참여자 인증이 필요한 경계에서는 서버가 약속 소속·세션·현재 역할·상태를 검사한다. 공개 링크 안내와 외부 챗봇은 각 경계의 공개 범위·호출 검증을 적용한다. 다른 참여자의 민감 정보를 오류에 포함하지 않는다.

## 검증 계획

- AC별 검증 경계·원본 근거는 아래 표를 따른다. 실제 실행 근거는 [004 TDD 기록](../tdd/004-availability.md)에 기록한다.
- 단위 테스트 예정 명령: 프로젝트 루트에서 docker compose exec tools npm run test -- src/lib/availability/availability.test.ts.
- DB 통합 예정 명령: docker compose exec tools npm run test:integration -- src/lib/availability/availability.integration.test.ts. 001에서 도입한 격리 sdd_test 보호·마이그레이션·통합 실행기를 재사용한다. DB 검증 항목이 없는 AC에 억지로 통합 테스트를 만들지 않는다.
- DB 변경이 있으면 전용 테스트 DB 보호 확인 → 로컬 마이그레이션 작성 → Client 생성 → 빈 테스트 DB에 기존 마이그레이션 적용 → 실제 제약·트랜잭션 검증 순서로 진행한다. 운영 적용은 별도 배포 요청 시 db:deploy로만 한다.
- 격리: TEST_DATABASE_URL과 테스트 DB 이름·로컬 호스트 허용 목록을 검사하고 개발·운영 URL을 거절한다. 동시성은 독립 연결과 동시 시작 장벽을 사용한다. 상세 구성은 분해 계획에 정의한다.
- 브라우저 동작·오류 복구·모바일을 실제 확인한다. 이미지가 있는 요소는 원본 1280×3042 참고 시트를 사용한다. 제품 화면은 기존 사용자 기준 393×852·1280×800과 좁은 320px에서 검수하며 디자인 원본 크기로 주장하지 않는다.
- 최종 검증: 관련 단위·DB·브라우저 회귀, Docker Node.js 24의 npm run lint, npm run typecheck, npm run build. 필요한 검증을 실행하지 못하면 미검증으로 남긴다.

- 전송: 앱 폼은 `submitAvailability` Server Action. HTTP GET/POST `/p/[inviteToken]/availability/state`는 private/no-store, 충돌 409, 세션 없음 401, 출처 실패 403을 반환한다. POST와 Action 모두 같은 검증을 거치며 저장 대상은 세션에서만 정한다. 앱은 화면을 연 참여자의 expectedParticipantId를 함께 보내 로그인 대상 변경을 검증한다. 이 기대값으로 저장 대상을 지정할 수 없다.
- 시간/저장: 약속 행 잠금 뒤 `clock_timestamp()`로 판단한다. 마감 쓰기는 closed를 커밋하고 제출을 거절한다. 조회는 효과상 마감만 반환하고 DB 상태를 바꾸지 않는다. 정규화 뒤 최종 집합·제출 상태를 비교해 오래된 동일 결과 재시도에 버전을 더하지 않는다.
- 마감 후에는 본인 저장 응답을 읽기 전용으로 제공하고 기존 약속 정보로 돌아갈 수 있다. 전체 현황·후보·결과 화면은 005/006 후속 범위로 유지한다.
- 다른 탭에서 로그인 주체가 달라지면 이전 화면 제출을 거절하고, 폴링에서 주체 변경을 감지하면 약속 페이지로 이동한다.
- 신규 정책 결정 없음. OPEN-08 반복 적용, 운영 배포·외부 기록은 수행하지 않는다.

- 시작 단계 검증: 단위 16개·DB 48개·Chromium 24개·린트·타입·빌드 통과. 320/393/1280px 캡처 확인. 필수 AC의 미충족 없음, 별도 검토·테스트·완료 단계는 다음 요청으로 수행한다. 실제 iPhone Safari·Neon/Vercel 운영은 미검증이다.

## 사용자 화면 보완 — 2026-11-14

아래는 시간순 변경 이력이다. 오늘 버튼·선택 요약·설명 표시·초기화 UI의 현재 기준은 마지막 「최종 편집 도구 보완」과 AC-8을 따른다.

## 시간표 축척·편집 복구 — 2026-11-14

- 사용자 요청: 모바일의 긴 시간표를 30분/1시간/2시간 보기로 바꾸고, 실수한 드래그 되돌리기 및 현재 주 초기화를 제공한다.
- 한 칸을 보기 단위로 묶되 저장 데이터는 기존 30분 슬롯을 유지한다. 확대·축소로 기존 선택을 바꾸지 않고 일부만 선택된 묶음은 별도 표시한다. 선택은 해당 칸의 편집 가능한 미래 슬롯에만 적용하고 하루 마지막의 짧은 묶음은 종료 범위까지만 선택한다.
- 2026-11-14 완료 후 사용자 결정: 처음 진입하거나 새로고침할 때 기본 보기는 1시간이다. 사용자는 30분·2시간으로 전환할 수 있고 저장 단위는 30분을 유지한다.
- 되돌리기는 드래그 전체·탭/키보드 선택·이번 주 초기화 각각을 한 작업으로 기록한다. 최근 50개까지 현재 화면의 임시 입력만 복구한다. 성공 제출·다른 기기 변경·설정 변경·마감 전환 시 기록을 비운다. 조회 실패나 제출 실패에는 유지한다.
- 이번 주 초기화는 현재 보이는 일~토의 편집 가능한 선택만 지우고 다른 주와 이미 지난 슬롯은 보존한다. 제출 전 로컬 작업이며 되돌릴 수 있다.
- 날짜별 반복 적용은 이번 요청에서 구현하지 않는다. 005 비교 보기와 별개로 004의 입력 편의 기능을 보완한다.

- 사용자 시각 보완: 되돌리기는 꺾인 화살표, 이번 주 초기화는 원형 화살표 아이콘 버튼으로 표시한다. 22px SVG와 44×44px 터치 영역, 기존 파란색 계열을 적용하고 접근성 이름·툴팁으로 의미를 유지한다. 동작과 초기화 범위는 동일하다.
- 1시간·2시간 보기의 시간 축은 정각의 분을 생략해 `09 ~ 10`, `09 ~ 11`로 표시한다. 실제 30분 시각은 `09:30`처럼 유지하며 30분 보기와 저장 단위는 변경하지 않는다.

### 최종 편집 도구 보완 — 2026-11-14

- 후속 사용자 결정으로 오늘 버튼과 편집 아이콘 아래 설명을 제거한다. 기존 오늘 위치에 되돌리기(왼쪽 화살표)·복구하기(오른쪽 화살표)를 두고, 보기 단위는 오른쪽을 유지한다. 화살표는 접근성 이름과 PC 툴팁으로 구분한다.
- 복구하기는 마지막 되돌리기를 역순으로 복구한다. 새 선택·해제·초기화로 변경되면 복구 이력을 버리고, 성공 제출·서버 응답/설정/상태 변경 시 되돌리기와 복구 이력을 함께 비운다. 주 이동·축척 변경은 기록을 유지한다.
- 초기화는 제출 버튼 왼쪽에 텍스트 버튼으로 둔다. 누르면 `이번 주 선택을 지울까요?` 안내창에서 현재 주만 지우는 범위를 설명하고 `취소`·`초기화`를 제공한다. 취소/Escape는 선택을 유지하고, 확인한 초기화는 되돌리기·복구하기 대상이다. 서버 갱신 시 열린 확인창을 닫는다.
- 후속 승인으로 안내창을 `선택한 시간을 초기화할까요?`로 바꾸고 `이번 주 초기화`·`전체 초기화`·`취소`를 제공한다. 전체 초기화는 모든 주의 미래 선택을 지우며 이미 지난 슬롯은 보존한다. 미래 선택이 어느 주에든 있으면 창을 열 수 있고, 현재 주가 비면 이번 주 초기화만 비활성화한다. 전체 초기화도 로컬 변경 한 건으로 되돌리기·복구하기가 가능하며 `선택 제출` 전에는 서버 응답을 바꾸지 않는다.
