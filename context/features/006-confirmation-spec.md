## 데이터와 인터페이스

promises.confirmed_start_at·status를 원자적으로 갱신한다. 종료시각·확정 버튼을 누른 시각·후보 이력 테이블을 새로 저장하지 않는다. Server Action `confirmPromise(inviteToken,startAt,expectedParticipantId)`와 서버 서비스 `confirmationService.read({inviteToken,sessionToken})`를 사용한다. 초대 토큰을 아는 것만으로 결과를 공개하지 않는다. 서버는 같은 약속의 active 참여자 세션을 확인한 후 결과를 반환한다.

공통 잠금·서버 시각·오류 계약·DB 테스트 기준은 [분해 계획](../spec-plan.md)의 공통 구현·검증 계약을 따른다. 참여자 인증이 필요한 경계에서는 서버가 약속 소속·세션·현재 역할·상태를 검사한다. 공개 링크 안내와 외부 챗봇은 각 경계의 공개 범위·호출 검증을 적용한다. 다른 참여자의 민감 정보를 오류에 포함하지 않는다.

## 2026-11-15 구현 계약

- `/p/[inviteToken]/result`는 인증된 결과 화면, `/result/state`는 private/no-store 폴링 조회다. 인증이 없으면 기존 참여자 로그인으로 안내하고 상세 결과를 전달하지 않는다.
- 확정 입력은 시작 시각과 화면의 본인 ID만 받는다. 잠금 후 현재 방장·유효 상태·현재 DB 시각·기존 005 후보 계산으로 검증한다. 기한이 지난 collecting은 쓰기 경계에서 closed로 반영한다.
- 동일 확정 시각의 재요청은 멱등 성공, 다른 시각은 ALREADY_CONFIRMED로 최신 결과를 안내한다. 첫 확정 이후 덮어쓰기하지 않는다. 이 계약은 네트워크 재시도·동시 확정의 기술 설계다.
- 확정 결과의 참석자는 현재 active·제출 완료이며 전체 소요 시간의 슬롯을 가진 사람이다. 과거가 된 확정 결과도 조회하며, 2명 미만이어도 상태를 자동 변경하지 않는다.
- 기존 Prisma 모델/마이그레이션을 재사용한다. 결과 티켓은 기존 파란색·타이포와 간결한 문구를 사용한다.

## 2026-11-15 사용자 결정 — 마감과 후보 화면 분리

- 모집 중 방장용 `응답 마감` 버튼은 상단 오른쪽에 배치하고 헤더는 스크롤 시에도 유지한다. 기존 확인 창과 미제출 선택 안내를 유지한다.
- 마감 후 기본 진입은 `/p/[inviteToken]/candidates`다. 수동 마감 성공·기한 경과·다른 기기 마감을 확인하면 후보 화면으로 이동한다. 참여자도 후보를 보되 방장만 확정한다.
- 후보 화면의 `응답 시간표 보기`는 `/availability?view=responses`로 이동해 기존 내 시간/전체 시간/참여자별 비교를 읽기 전용으로 제공한다. 명시적으로 연 시간표는 폴링 때 후보 화면으로 강제 복귀하지 않는다. 상단 `후보 보기`로 돌아간다.
- 모집 중 후보 주소 접근은 시간 입력으로, 확정 후 접근은 결과 티켓으로 이동한다. 인증·취소·만료 우선순위는 유지한다.
- 동작 변경은 실제 브라우저 RED→GREEN, 상단 고정·배치는 모바일/PC 시각 검수로 확인한다. 후보 계산·DB 저장 정책 변경은 없다.
- 후속 화면 변경 검증: 전체 Chromium 52개·린트·타입·빌드 exit 0, 320/393/1280px 시각 검수. 상세 근거는 [006 TDD 기록](../tdd/006-confirmation.md)과 [수정 기록](../fixes/006-candidates-navigation.md)에 남겼다.

## 2026-11-15 확정 티켓 시각 개선

- 사용자가 제공한 전시 입장권 이미지의 분리된 표지·절취면·흰 종이·바코드 구성을 참고한다. 기존 파란색을 중심으로 자체 SVG 표지 그림, 종이 질감, 확정 도장, 절취선과 장식 바코드를 적용했다.
- 날짜·시간·참석자·결과 링크 복사와 인증/갱신 동작은 유지한다. 장식 바코드는 토큰·개인정보를 인코딩하지 않으며 스캔/입장 인증 기능은 추가하지 않는다.

## 2026-11-25 후속 — 연속 후보 표시와 명단

공식 후보 목록은 같은 참석자 집합의 연속 시작점을 하나의 가능 구간으로 묶은 뒤 정렬·페이지 분할한다. 구간을 누르면 전체 구간 참석 닉네임을 펼치며, 방장은 별도 확정 창에서 구간 내 시작 시간을 골라 설정된 소요 시간으로 확정한다. 기존 30분 시작점 계산은 서버의 유효성 검증용으로 유지한다. 상세 정책과 검증은 [연속 후보 스펙](candidate-ranges-spec.md), [TDD 기록](../tdd/candidate-ranges.md)을 따른다.

## 2026-11-25 후속 — 최소 길이와 실제 확정 길이 분리

사용자가 업다운 시안을 확인한 뒤 실제 저장 연결을 승인했다. 최소 소요 시간은 기존 durationMinutes에 유지하고 실제 종료 confirmedEndAt을 별도로 저장한다. 앞선 ‘종료 시각을 저장하지 않는다’는 정책은 이번 요청에서 변경됐다. 후보 전체를 기본 선택하며 같은 후보 안에서 시작/종료를 30분 단위로 조절한다. 결과는 실제 전체 구간의 길이와 참석자를 보여주고 재조율은 시작·종료를 함께 지운다.
