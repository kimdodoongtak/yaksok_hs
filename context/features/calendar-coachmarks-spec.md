# 시간 입력 첫 방문 안내

상태: 구현·검토·검증 완료 (2026-11-25). 최초 3단계 구현 뒤 사용자 피드백으로 도입·작은 말풍선·5단계·첫 진입 자동 노출·종료 기억으로 변경했다. 관련 안내 16개를 포함한 전체 브라우저 122개와 필수 검사 통과. 커밋·푸시·배포 요청으로 기존 로컬 보류를 해제했다. [전체 검증 기록](../tdd/calendar-ui-polish.md).

2026-11-25 노트북/안내 오류 수정: 실제 브라우저 검증을 진행했다. [실행 결과](../tdd/calendar-coachmarks.md). 아래 테스트·배포 보류 기록은 당시 이력이다.

## 범위와 수용 기준

- AC1 (2026-11-25 최신 변경): 모집 중인 내 시간에서 브라우저에 안내 종료 기록이 없으면 자동 안내한다. ‘바로 시작하기’·‘건너뛰기’·마지막 ‘시작하기’·Escape로 닫으면 같은 브라우저의 새로고침·재진입·다른 약속에서 자동으로 다시 띄우지 않는다. localStorage의 `yaksok:availability-guide:v1=seen`으로 기억하며 접근이 제한되면 sessionStorage를 사용한다. 두 저장소 모두 제한된 경우에도 종료 자체는 가능하다. 이전의 매번 진입 시 표시 정책을 대체한다. 사용법 버튼의 수동 재실행은 항상 허용한다.
- AC1 후속: 자동 안내는 곧바로 첫 단계 대신 도입 화면을 먼저 표시한다. 달력 아이콘, “가능한 시간을 알려주세요”, “시간 선택부터 제출까지, 사용법을 짧게 안내해 드릴게요.”를 보여준다. ‘사용법 보기’로 5단계를 시작하고 ‘바로 시작하기’ 또는 Escape로 입력 화면에 진입한다. 사용법 버튼으로 재실행할 때는 도입을 생략하고 첫 단계부터 표시한다. 도입은 단계 수에 포함하지 않는다.
- AC2: 조작 방법 → 시간표 → 시간 선택 단위 → 주간 반복 → 선택 제출의 5단계로 해당 영역을 밝게 강조한다. 단계 번호·다음·이전·건너뛰기를 제공하고 마지막 버튼은 시작하기로 표시한다. 길게 누르기를 요구하는 문구는 쓰지 않는다. 카드 폭 240~260px·제목 16px로 줄이고 대상 좌우에 맞춰 배치한다. 말풍선 꼬리와 강조 영역의 이동으로 설명 대상을 연결하며 동작 줄이기 설정에서는 이동 전환을 생략한다. 하단 버튼 안내는 버튼 위에 우선 배치한다.
- AC3: 안내 중 실제 시간 선택·제출·뒤쪽 스크롤을 막는다. 안내 종료는 기존 선택 값·선택 모드를 변경하거나 자동 제출하지 않는다. 기본 스크롤 모드도 유지한다.
- AC4: 내 시간의 도움말 옆 사용법으로 다시 볼 수 있다. 날짜 보기에서 실행하면 시간표 보기로 전환하되 선택 값은 유지한다. 마감·제출 처리 중에는 실행하지 않는다.
- AC5: 모달 포커스를 가두고 Escape로 종료한다. 재실행 종료 뒤 사용법 버튼으로 포커스를 복원한다. 안내 버튼 높이는 최소 44px, 사용법은 시각적 높이를 유지하면서 터치 영역을 확장한다. 작은 화면에서는 안내 카드가 화면 안에 놓이도록 위치·높이를 제한한다.
- AC6: 노트북 1366×768 최초 화면에서 시간표 폭 850px 이상, 완전한 시간 행 6개 이상을 제공한다. 데스크톱 중복 제목/진행 표시의 시각적 공간을 줄이고 1200px 이상에서는 날짜 이동과 조작 버튼을 같은 줄에 배치한다. 모바일 시트 배치는 유지한다.
- AC7: 단계 전환 시 대상이 화면 밖에 있다면 실제 대상을 먼저 보이도록 스크롤한 뒤 설명을 배치한다. 시간표는 고정 상단과 하단 제출부 사이의 보이는 행만 강조한다. 전체 화면 SVG 마스크로 배경을 덮어 카드 이동·넓은 화면에서도 어두운 배경의 바깥 끝이 드러나지 않는다.
- AC8: 900px 이상에서는 브랜드·시간 보기 탭을 공통 상단 줄에 두고 일정 정보와 캘린더 카드의 시작선을 일치시킨다. 09:00~24:00처럼 긴 시간표는 카드 전체 높이로 이어지고 카드 내부의 별도 스크롤을 만들지 않는다. 900/1024×600에서도 완전한 시간 행 6개 이상을 보여준다. 날짜 이동과 조작부 한 줄 배치를 900px 이상에 적용한다(AC6의 1200px 기준을 대체).
- AC9: 첫 도입 팝업의 두 버튼은 최소 44px 높이·동일 너비·8px 이상 간격의 세로 배치이며 320px~노트북 화면 안에 들어온다. 최신 코드의 새 브라우저 검증뿐 아니라 실제 로컬 서버가 제공하는 스타일도 확인한다.

시간 단위·주간 반복 안내를 포함한다. 실제 칸을 칠하게 하는 연습 단계는 이번 범위에 포함하지 않는다. 로그인 인증 로직은 변경하지 않고 시간표 컴포넌트 진입 시 자동 노출한다.

## 검증 계획

AC1~4 상태·자동 노출·선택 보존, AC5 키보드·모달 동작은 동작 검증 대상이다. 색상·배치·여백 자체는 TDD 비대상으로 화면 검수가 필요하다. 320/393px 및 짧은 노트북 화면, 재실행, 안내 종료 후 자동 노출 방지, 마감 전환, 모바일 터치 시작→이동→해제를 확인한다.

사용자가 테스트를 나중에 요청하기로 해 이번에는 테스트 작성·실행과 린트·타입·빌드·브라우저 검수를 보류한다. 사후 검증 시 실제 결과를 기록하며 RED→GREEN을 수행한 것으로 소급하지 않는다. [미검증 기록](../tdd/calendar-coachmarks.md).

위 보류는 초기 구현 시점의 기록이다. 후속 오류 수정에서 AC6·AC7의 화면 재현 실패와 수정 후 통과를 확인했으며, 기존 안내·터치·제출 흐름은 사후 회귀 검증했다. 전체 기존 E2E 스위트와 실제 휴대전화 검증은 수행하지 않았다.
