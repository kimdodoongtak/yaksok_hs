# 시간 입력 조작 안내 개선

> 2026-11-24 사용자 요청으로 조작 안내 UI 변경을 철회하고 관련 코드·테스트를 원복했다. 아래 내용은 시도 기록이다. 1시간 보기의 시작 시각 표시만 로컬에 유지하며 원복 후 테스트·커밋·배포는 실행하지 않았다.

2026-11-24 사용자 요청. 설명 없는 단위·모드 버튼을 처음 사용하는 사람도 이해할 수 있도록 바꾼다.

## 수용 기준

1. 내 시간 입력에 “가능한 시간을 알려주세요”, “선택 단위”와 `30분씩 · 1시간씩 · 하루씩`을 표시한다. 기본 1시간과 선택값 보존은 유지한다. 읽기 전용 화면에는 “보기 단위”로 표시한다.
2. 터치 시간표에서는 두 모드 버튼 대신 `시간 선택 시작` 하나를 제공한다. 누르면 선택 모드가 되고 `스크롤로 돌아가기`로 바뀐다. 복귀는 선택을 보존하며 저장하지 않는다. 제출·다른 보기 전환 시 기본 스크롤 복귀를 유지한다.
3. 기본 터치 상태는 “지금은 시간표를 위아래로 둘러볼 수 있어요.”, 선택 중에는 누르기·쓸기 안내를 표시한다. 마우스는 기존 직접 선택 동작과 그에 맞는 안내를 제공한다. 하루씩 보기는 시작 버튼 없이 날짜를 눌러 선택·해제한다는 안내를 제공한다.
4. 320·393px에서 버튼이 겹치거나 가로로 넘치지 않고 주요 버튼 높이는 44px 이상으로 한다. 단위·모드 버튼 가장자리 탭, 넓은 접촉 면적을 설정한 스와이프에서도 스크롤 시작이 선택·버튼 실행으로 이어지지 않아야 한다. 선택 모드의 칸·여백과 바깥 스크롤 동작을 회귀 검증한다.

## 범위와 검증

- 친구들 시간 겹쳐 보기와 칸 높이 변경은 후속이다. 기존 데이터·제출·조회·시간 계산 정책은 유지한다.
- TDD 대상: AC2의 단일 버튼 전환과 선택 보존. 기존 모바일 E2E를 새 조작 흐름에 맞춰 실제 RED→GREEN으로 확인한다.
- TDD 비대상: 정적 문구·CSS. 기존 단위·날짜·제출·스크롤 테스트를 갱신해 회귀 검증하고 320·393·1280px 화면을 검수한다. 테스트는 Docker Node.js 24, 격리 DB만 사용한다.
- 명령: `npm run test:browser -- e2e/availability.spec.ts e2e/candidates.spec.ts e2e/rescheduling.spec.ts`, `npm run test`, `npm run lint`, `npm run typecheck`, `npm run build`.
- 터치 에뮬레이션과 실제 기기 검증을 구분한다. 실행 근거는 [TDD 기록](../tdd/calendar-input-guidance.md)에 남긴다.
