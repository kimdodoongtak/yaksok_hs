# 후보 안에서 시작·종료 조절

2026-11-25 사용자 승인. 상태: 실제 저장 연결·로컬 검증 완료. 로컬 구현, 기존 변경·데모 보존.

- 후보 전체 구간을 초기 선택한다. 시작/종료 옆 위아래 버튼으로 각각 30분씩 조절한다.
- 후보 경계 밖 또는 최소 소요 시간 미만으로 만드는 버튼은 비활성화한다. 버튼 접촉 영역은 최소 44px이며 모바일에서 스크롤과 터치를 구분한다.
- 실제 시작·종료·총 길이를 보여주고 명시적 확정 버튼에서만 저장한다. pending 동안 조절/중복 저장을 막는다.
- 서버는 현재 방장·세션·상태·미래·30분 경계·최소 길이·최신 연속 후보 안에 포함되는지 잠금 안에서 재검증한다.
- 설정 durationMinutes는 최소 소요 시간으로 유지한다. 실제 종료 confirmedEndAt을 별도 저장하며 결과 화면의 길이·명단은 전체 실제 구간을 기준으로 계산한다.
- 기존 종료 미저장 확정은 시작+기존 소요 시간으로 호환한다. 마이그레이션에서 기존 값도 채우며 새 확정은 시작·종료를 원자 저장한다. 동일 시작/다른 종료를 덮어쓰지 않는다.
- 재조율은 시작·종료를 함께 해제한다. 취소는 기존 확정 기록을 보존한다.

실제 DB RED/GREEN, 동시 확정·종료 경계·명단·재조율 회귀와 모바일 브라우저 조절·실제 저장으로 검증한다. 정적 스타일은 TDD 비대상이며 캡처 검수. 변경은 로컬만 적용한다.

## 최신 범위 — UI 먼저 확인

사용자가 DB 변경 이유를 확인한 뒤 ‘UI만 먼저 보여줘’로 범위를 좁혔다. 저장 구현의 추가 진행·배포는 보류하고 `/preview/time-adjustment` 개발 전용 화면에서 정적 09~13시·5명·최소 2시간을 조절한다. 미리보기 확정은 서버 액션을 호출하지 않는다. 이미 추가한 로컬 컬럼·진행 중 코드는 임의 삭제하지 않고 보존한다. 운영 DB 변경 없음.

## 최신 승인 — 실제 저장 연결

사용자가 시안을 승인하고 ‘연결 해’라고 요청했다. 기존 실제 저장 구현을 이어서 검증해 로컬 후보 화면에 적용한다. 미리보기 주소는 저장하지 않는 별도 데모로 유지하며, 실제 동작은 인증된 기존 약속 후보 주소에서 제공한다. 운영 DB 적용·배포는 요청 범위 밖이다.
