## 수용 기준

- [x] AC-1: GET은 deadline≤현재이면 effectiveStatus=closed로 응답하지만 DB status를 변경하지 않는다. 전원 제출은 마감 사유가 아니며 응답이 0명·1명이어도 기한이 지나면 유효 마감이다.
- [x] AC-2: 방장 조기 마감과 기한 도달 후 변경 요청은 같은 약속 잠금 규칙을 따른다. 늦은 슬롯·신규 등록은 거절하고 필요한 closed 전환은 커밋한다. 조회용 API를 쓰기 트리거로 사용하지 않는다.
- [x] AC-3: active·제출 완료 참여자만 후보에 집계한다. 전체 날짜 범위의 미래 30분 시작점 중 소요 시간 전체가 동일 날짜 선택 경계에 드는 후보를 계산한다.
- [x] AC-4: 구간 전체의 동일 참여자 교집합이 2명 이상이어야 한다. 10:00 {A,B}, 10:30 {B,C}인 60분 구간은 공통 1명이므로 제외한다. 방장이 불가능해도 다른 2명이 연속 참석 가능하면 포함한다.
- [x] AC-5: 가능 인원 내림차순·시작 시각 오름차순으로 정렬해 상위 5개를 기본 표시하고 나머지를 조회할 수 있다. 과거가 된 후보를 제외하며 미래 유효 후보가 없으면 closed를 유지하고 안내한다.
- [x] AC-6: 히트맵은 슬롯별 인원이며 공식 후보 인원과 구분한다. 사용자가 요청한 전체 시간 보기에서 제출 완료 응답만 집계하고 모집 중에는 임시 표시를 한다. 미제출·빈 제출은 가능 인원 0으로 처리하고 분모는 active 전체다. 타인의 제출 여부는 응답에 공개하지 않는다.
- [x] AC-7: 같은 인원수라도 참석자 집합이 다른 구간을 같은 공통 구간으로 합치지 않는다. 후보·인원수·색상·순위는 계산값으로 두고 별도 후보 테이블에 저장하지 않는다.
- [x] AC-8: 모집·마감·로딩·연결 실패·후보 없음과 더 보기를 실제 브라우저에서 확인한다. 히트맵 색상과 인원 숫자를 이미지와 비교한다.
- [x] AC-9: 인증된 같은 약속의 active 참여자 목록을 사이드바에 표시하고 이름 선택 시 그 사람의 서버 제출 시간을 읽기 전용으로 보여 준다. 내 시간/전체 시간 전환 시 현재 주·스크롤 위치와 로컬 미제출 선택을 유지한다. 타인 제출 여부·시각은 노출하지 않고 미제출·빈 제출은 같은 빈 선택으로 보여 준다.

## 데이터와 인터페이스

새 후보 테이블 없이 promises·participants·slots를 조회한다. createCandidatesService.read/close와 Server Action closeCollection(inviteToken,expectedParticipantId)을 구현했다. 브라우저 폴링은 인증된 읽기 전용 GET /p/[inviteToken]/overview를 사용한다. 본인 편집 데이터는 기존 /availability/state에서 별도로 갱신한다.

overview 응답의 status에는 유효 상태를 담고, settings·본인 participantId·공개 참여자 명단·선택 대상의 제출 슬롯·현재 주 히트맵/선택자 인덱스·주간 후보·공식 후보를 반환한다. 본인의 버전·제출 상태·편집 슬롯은 별도 availability/state에서 조회한다. 타인의 제출 시각·PIN·세션은 제외한다. 후보 추가 조회는 기준 시각과 정렬의 일관성을 설계하고 시간 경과 시 최신 목록을 다시 불러온다.

공통 잠금·서버 시각·오류 계약·DB 테스트 기준은 [분해 계획](../spec-plan.md)의 공통 구현·검증 계약을 따른다. 참여자 인증이 필요한 경계에서는 서버가 약속 소속·세션·현재 역할·상태를 검사한다. 공개 링크 안내와 외부 챗봇은 각 경계의 공개 범위·호출 검증을 적용한다. 다른 참여자의 민감 정보를 오류에 포함하지 않는다.

## 검증 계획

- AC별 검증 경계·원본 근거는 아래 표를 따른다. 실제 실행 결과는 TDD 기록에 남긴다.
- 단위 테스트 예정 명령: 프로젝트 루트에서 docker compose exec tools npm run test -- src/lib/candidates/candidates.test.ts.
- DB 통합 예정 명령: docker compose exec tools npm run test:integration -- src/lib/candidates/candidates.integration.test.ts. 001에서 도입한 전용 PostgreSQL 테스트 환경과 test:integration 명령을 재사용한다. DB 검증 항목이 없는 AC에 억지로 통합 테스트를 만들지 않는다.
- DB 변경이 있으면 전용 테스트 DB 보호 확인 → 로컬 마이그레이션 작성 → Client 생성 → 빈 테스트 DB에 기존 마이그레이션 적용 → 실제 제약·트랜잭션 검증 순서로 진행한다. 운영 적용은 별도 배포 요청 시 db:deploy로만 한다.
- 격리: TEST_DATABASE_URL과 테스트 DB 이름·로컬 호스트 허용 목록을 검사하고 개발·운영 URL을 거절한다. 동시성은 독립 연결과 동시 시작 장벽을 사용한다. 상세 구성은 분해 계획에 정의한다.
- 브라우저 동작·오류 복구·모바일을 실제 확인한다. 이미지가 있는 요소는 원본 1280×3042 참고 시트를 사용한다. 제품 화면 검수 크기는 390×844와 1280×800을 제안하며 디자인 원본 크기로 주장하지 않는다.
- 최종 검증: 관련 단위·DB·브라우저 회귀, Docker Node.js 24의 npm run lint, npm run typecheck, npm run build. 필요한 검증을 실행하지 못하면 미검증으로 남긴다.

## 사용자 화면 방향 — 2026-11-14

- 사이드바의 작은 월 달력은 제거한다. 주 이동은 기존 시간표의 이전/다음으로 유지한다. 오늘 버튼은 후속 사용자 결정으로 제거했다.
- 사이드바를 참여자 목록 중심으로 구성하고 이름을 누르면 해당 사람의 선택 시간만 본다. 모바일에서 이름 선택 후 서랍을 닫고 시간표를 보여 주는 안으로 구현한다.

- 참여자별 보기에서는 대상 이름을 명시하고 내 시간/전체 시간으로 돌아갈 수 있게 한다. 보기 전환은 현재 주와 스크롤 위치를 유지하고 본인의 미제출 입력을 버리거나 자동 제출하지 않는다. 서버 버전/settings 변경 시 동기화 규칙은 004를 따른다.
- ERD의 제출 여부 비공개 정책을 유지한다. 참여자 목록에 타인의 ‘제출 완료/응답 대기’ 배지를 붙이지 않고, 미제출·빈 제출은 같은 빈 슬롯 표현을 사용한다. 공개 데이터는 같은 약속의 인증된 active 참여자에게만 제공한다.

## 2026-11-15 빈 슬롯 표시 보정

## 2026-11-15 색상 히트맵과 후보 표시

- 후속 사용자 결정으로 모든 일반 슬롯의 인원 숫자 표시를 제거한다. 응답 분포는 색상으로만 표현한다.
- 동일 참여자 2명 이상이 약속 소요 시간 전체를 연속 참석 가능한 미래 후보에만 시간 범위·공통 인원을 표시한다. 단순 슬롯별 인원 2명으로 후보를 판단하지 않는다.
- 모집 중에는 해당 주의 임시 후보를 표시하고, 마감 후 공식 상위 후보 목록은 기존 정책을 유지한다. 주간 표시는 상위 5개 제한과 독립적이다.
- 1/2시간 보기의 한 칸에 여러 시작 후보가 있으면 우선 후보의 시간·인원을 표시하고 눌러 그 칸의 모든 시작 후보를 확인한다. 배경은 계속 30분별 히트맵이며 서로 다른 참석자 집합의 후보를 합치지 않는다.

## 2026-11-15 색상 범례·누르는 동안 참여자 표시

- 기존 설명 문구 대신 현재 active 참여자 수에 따른 색상별 인원 범위를 표시한다. 기존 4단계 비율을 유지하며 해당 인원이 없는 색상 단계는 생략한다. 예: 전체 5명 → 1명 / 2명 / 3명 / 4~5명, 별도 0명.
- 전체 시간의 색칠된 30분 칸은 누르는 동안 그 칸의 선택자 이름·시간을 보여 준다. 포인터를 떼거나 취소·칸 이탈·스크롤·창 전환하면 닫힌다. 키보드 Enter/Space 누름·해제와 Escape도 지원한다.
- 기존 후보 시간·인원 라벨은 유지한다. 지속되는 후보 클릭 창 대신, 각 30분 시작점의 후보 정보도 누르는 동안 함께 확인한다. 선택자 이름은 해당 30분 슬롯 기준이며 소요 시간 전체의 공통 후보 인원과 구분한다.
- 서버 집계와 동일하게 같은 약속 active·제출 완료 참여자만 선택자로 제공한다. 응답의 공개 참여자 목록 인덱스로 해당 주의 슬롯 선택자를 연결하며 닉네임·UUID를 슬롯마다 반복 전송하지 않는다. 타인 제출 메타데이터는 계속 비공개다.

## 2026-11-15 범례를 색상 막대로 단순화

- 후속 사용자 참고 이미지에 따라 인원별 개별 숫자를 제거한다. 왼쪽 0명, 오른쪽 현재 전체 인원수만 표시하고 그 사이에 옅은색→진한색의 연속된 단계형 막대를 둔다.
- 색상은 기존 파란색 히트맵과 동일하게 유지한다. 중간 단계마다 숫자를 붙이지 않으며 누르는 동안 선택자 이름을 보여주는 동작은 유지한다.

## 2026-11-15 선택자 말풍선 디자인

- 사용자 요청으로 선택자 안내를 눌린 칸을 가리키는 작은 말풍선으로 구성한다. 시간·인원 배지와 이니셜이 붙은 이름표, 짧은 등장 효과를 사용한다.
- 이름이 많으면 이니셜을 생략한 촘촘한 이름표 배치로 모든 이름을 읽을 수 있게 한다. 화면 경계에 맞춰 말풍선 위치를 보정하고 칸을 가리킬 수 없는 위치에서는 꼬리를 숨긴다.
- 누르는 동안 표시·해제 시 즉시 닫기·선택자 공개 기준은 유지한다. 동작 줄이기 환경에서는 등장 애니메이션을 사용하지 않는다.

## 2026-11-15 선택자 안내 최종 간소화

- 후속 사용자 결정으로 위 말풍선의 시간·인원 배지·이니셜·후보 상세를 제거한다. 누른 칸 오른쪽에 닉네임만 둥근 말풍선으로 표시한다. 오른쪽이 좁으면 왼쪽, 양쪽 모두 부족하면 화면 안으로 위치를 보정한다.
- 큰 카드 배경 없이 이름별 말풍선으로 구성하며, 많은 인원은 다열로 배치한다. 누름·해제 동작과 시간표 자체의 후보 시간·인원 표시는 유지한다.

## 2026-11-15 원형 말풍선과 시간칸 연결

- 시간·인원 배지는 추가하지 않으며 누름 해제 시 즉시 사라지는 동작을 유지한다.
