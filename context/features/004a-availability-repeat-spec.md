## 근거 자료

- 대화에서 사용자가 제공한 반복 화면안: 주간 반복·특정 날짜 선택·반복 적용 후 저장 흐름.
- [004 스펙](004-availability-spec.md), [분해 계획](../spec-plan.md)의 OPEN-08.
- 기존 PRD·ERD에는 반복 입력의 상세 규칙이 없다. 2026-11-14 사용자 결정: 요일 반복으로 구현한 뒤, 후속 결정으로 현재 화면의 한 주를 반복하는 방식으로 변경한다. 기존 선택에 추가하고 지난 대상 시간·범위 밖 제외, 되돌리기·명시적 제출 방식을 적용한다.

## 사용자와 문제

여러 날짜에 같은 가능 시간을 입력할 때 긴 시간표를 반복해서 드래그해야 한다.

## 목표와 범위

현재 화면에 표시된 일요일~토요일 한 주의 선택을 적용할 주들에 같은 요일·시간으로 복사한다. 특정 날짜 직접 선택은 후속으로 남긴다. 대상은 현재 약속의 본인 입력이며 반복 약속 생성·자동 제출은 포함하지 않는다.

## 선행 작업

004의 30분 슬롯 선택, 로컬 입력, 되돌리기·복구하기, 제출과 서버 변경 동기화를 재사용한다.

## 사용자 흐름

시간 선택 → 반복 적용 열기 → 현재 보고 있는 기준 주 확인 → 적용할 주 선택 → 적용 → 시간표에서 확인 → 선택 제출.

모바일에서 우클릭 없이 열 수 있는 버튼과 대화상자를 사용한다. 적용 전 취소하면 입력을 유지한다. 기준 주의 요일별로 다른 시간과 떨어진 시간 구간도 그대로 복사한다.

## 수용 기준

- [x] AC-1: 기준 주의 현재 로컬 선택을 30분 슬롯 그대로 복사하며 1시간/2시간 보기에서도 정밀도를 유지한다.
- [x] AC-2: 사용자가 선택한 대상 주에만 같은 요일·시간을 추가한다. 화면의 주 경계(일~토)를 사용하며 대상 주의 일부가 약속 범위 밖이면 그 부분은 제외한다. 기준 주보다 앞이라도 미래 시간은 포함한다.
- [x] AC-3: 기존 선택과 합치고 중복을 만들지 않는다. 지난 대상 시간·약속 범위 밖 슬롯은 추가하지 않는다.
- [x] AC-4: 반복 적용 한 번을 한 번의 되돌리기로 취소하고 복구할 수 있다. 실제 변경이 없으면 이력을 추가하지 않는다.
- [x] AC-5: 적용은 로컬 선택만 바꾸며 선택 제출 때 기존 서버 검증으로 저장한다. 취소는 입력을 바꾸지 않는다.
- [x] AC-6: 마감·제출 중에는 적용할 수 없다. 서버 버전/설정/상태 변경으로 입력이 갱신되면 반복 대화상자도 닫고 이전 기준으로 적용하지 않는다.
- [x] AC-7: 모바일·PC에서 기준 주·대상 주·적용 결과를 확인하고 키보드로 대화상자를 조작할 수 있다.

## 데이터와 인터페이스

새 DB 모델 없이 기존 로컬 슬롯 Set과 제출 경계를 재사용한다. 반복 계산은 순수 함수, 대화상자는 별도 컴포넌트로 분리해 기존 편집기의 이력 처리와 연결한다.

## 구현 계획

정책 확인 → 반복 계산의 RED/GREEN → 대화상자와 이력 연결의 RED/GREEN → 서버 갱신/마감 경계 검증 → 회귀·화면 검수.

## 확정된 화면 동작

- 2026-11-14 후속 사용자 결정: 모바일에서 보이는 한 주 단위가 자연스러우므로 요일 반복을 한 주 반복으로 대체한다.
- 기준 주는 현재 보고 있는 주로 고정하고 요일별 선택 시간은 시간 보기를 펼쳐 확인한다. 현재 주에 선택이 없으면 버튼을 비활성화한다. 다른 주를 기준으로 삼으려면 기존 주 이동을 사용한다.
- 대상 주는 약속 기간과 겹치는 다른 주 중 미래 시간이 남아 있는 주를 여러 개 선택한다. 기본은 전체 선택이며 직접 선택으로 전환할 때만 대상 주 목록을 펼친다. 반복할 다른 주가 없으면 안내한다.
- 기존 선택에는 추가만 하며 빈 요일로 대상 주의 기존 시간을 지우지 않는다. 원본의 지난 슬롯도 시간 패턴으로 재사용할 수 있지만 대상은 서버 기준 미래만 추가한다.
- 적용 전에 새로 추가되는 주 수와 시간을 보여 준다. 취소·Escape·되돌리기/복구·명시적 제출·서버 변경 시 닫기는 유지한다.
- 구현을 막는 미정 정책 없음. 개별 요일/직접 날짜 반복은 이번 범위에서 제외한다.

## 결과

현재 화면의 한 주를 기준으로 선택한 대상 주에 같은 요일·시간을 추가하도록 변경했다. 기준 주의 요일별 패턴, 대상 주 체크박스, 추가될 주/시간 한 줄 미리보기를 제공한다. 기존 취소·되돌리기/복구·명시적 제출·서버 동기화를 유지한다.

새 단위 RED/GREEN과 주간 UI RED/GREEN, 관련 회귀의 근거는 [실행 기록](../tdd/004a-availability-repeat.md)에 있다. Docker Node.js 24의 전체 단위 18개·시간표 브라우저 22개·린트·타입·빌드 모두 exit 0. 320·393·1280px 화면 검수 완료. 실제 iPhone Safari·Neon/Vercel은 미검증이며 정식 검토 전 상태다. 이전 요일 반복의 실행 이력은 같은 기록에 보존한다.

## 전체 대상 선택 — 2026-11-14 중간 구현(아래 후속 결정으로 대체)

사용자의 전체 적용 버튼 요청을 반영해 ‘적용할 주’ 옆에 전체 선택/전체 해제 버튼을 둔다. 대상 주들을 한 번에 선택하고 기존 적용 버튼으로 로컬 입력에 반영한다. 일부 선택 상태에서 전체 선택을 누르면 나머지도 선택한다. 대상 주가 없으면 버튼을 표시하지 않는다. 서버 저장은 기존 선택 제출을 따른다. 기존 브라우저 시나리오에서 전체 선택·해제·부분 선택 후 재선택·키보드·터치·저장을 검증한다.

## 대상 주 목록 접기 — 2026-11-14 후속 결정

전체 선택 버튼 구현 후 사용자가 전체 선택을 하지 않을 때만 목록을 펼치도록 요청했다. 전체 선택/직접 선택 전환으로 정리한다. 기본은 전체 선택이며 바로 적용 가능하다. 직접 선택에서는 주 체크박스를 보여 주고 처음에는 선택하지 않는다. 모드 전환 중 직접 선택 내역은 보존하지만 실제 적용은 현재 모드만 따른다. 전체 선택으로 돌아가면 목록을 접는다. 적용/저장은 기존처럼 명시적으로 수행한다.
