## 사용자와 문제

초대 링크를 받은 최초 사용자가 명시적으로 방장을 등록하고 약속 설정을 시작한다. 링크 미리보기나 동시 접속으로 방장이 잘못 지정되지 않아야 한다.

## 목표와 범위

초대 토큰 발급 서비스, 링크 조회, 방장 등록, 초기 약속별 세션, draft 만료 안내·정리·나가기. 실제 카카오 요청 처리는 010, 모집 설정은 002, 재인증·일반 참여는 003에서 연결한다. 001 당시에는 웹 공개 발급을 제외했다. 2026-11-16 사용자 결정으로 [011 홈에서 약속 만들기](011-web-invitation-spec.md)에서 기존 발급 서비스를 연결한다.

## 선행 작업

## 사용자 흐름

유효한 미사용 링크 → 닉네임·PIN 입력 → 명시적 방장 등록 → 약속·방장·세션 생성 → 설정 화면 진입. 선점 중에는 진행 상태를 표시한다. 이미 선점된 링크는 draft 대기 또는 약속 진입 경로를 안내한다. 8분 경과 시 2분 남음 안내, 10분 경과 시 만료 안내. 조회만으로 삭제하지 않으며 다음 쓰기에서 만료 초안을 정리한다.

## 수용 기준

- [x] AC-1: 링크 발급은 promise_links만 생성한다. 링크 GET·미리보기는 약속·방장 생성이나 만료 초안 삭제를 일으키지 않는다.
- [x] AC-2: 동일 링크의 동시 방장 등록 2건 중 하나만 약속과 active host를 생성한다. 실패 시 약속·방장·세션의 부분 저장이 없다.
- [x] AC-3: 닉네임은 앞뒤 공백 제거·NFC 정규화 후 눈에 보이는 글자(확장 자소 클러스터) 기준 2~12자이며 이모지를 허용하지 않는다. 중간 공백은 유지하고 길이에 포함한다. 약속 내 중복 판정은 영문 대소문자를 구분하지 않으며 표시 이름의 대소문자는 보존한다. PIN은 숫자 4자리로 검증하고 선행 0을 보존한다. PIN 원문은 저장·로그·응답에 남기지 않는다.
- [x] AC-4: 약속별 난수 세션 토큰을 안전한 HttpOnly 쿠키로 발급하고 DB에는 해시만 저장한다. 세션·참여자·약속 검증 없이 설정 변경을 허용하지 않는다. draft 세션은 방장 등록 시각부터 10분 동안 유지하며 조회·새로고침으로 연장하지 않는다. 설정 완료·모집 시작 시 해당 세션을 응답 마감(voting_deadline_at) 후 7일까지 연장한다. 모집 시작과 연장의 실제 연결 검증은 002에서 수행한다. 세션 기한이 남아 있어도 초대 링크가 만료되면 접근을 허용하지 않는다.
- [x] AC-5: 방장 등록 후 10분 이상이면 draft를 만료로 판정한다. 만료 발견 쓰기와 draft 나가기는 링크→약속 순서로 잠그고 세션→방장→약속을 삭제하며 링크를 보존한다. 만료 직전 설정 완료와 경쟁해도 모집 중 약속은 삭제하지 않는다.
- [x] AC-6: Asia/Seoul 기준 발급 시각에서 달력 3개월 뒤 같은 시각을 링크 만료 시각으로 정한다. 해당 날짜가 없으면 대상 월의 마지막 날로 보정한다. 서버 시각이 만료 시각 이상이면 기존 방장·참여자와 유효 세션도 조회·변경·재인증으로 접근할 수 없고 화면에는 “만료된 약속입니다”만 표시한다. 약속 상세·참여자·결과는 노출하지 않으며 만료를 데이터 물리 삭제로 해석하지 않는다.
- [x] AC-7: 등록 중·선점 실패·잘못된 입력·만료 상태를 표시하고 draft에서 타인의 신규 참여를 막는다. 초안 만료 2분 전 안내와 서버 재판정, 초대 링크 만료 시 “만료된 약속입니다”만 표시되는 상태를 실제 브라우저에서 확인한다.

각 AC의 근거와 확인 방법은 아래 TDD 적용 계획에 대응한다. OPEN 항목이 포함된 AC는 해당 결정 전 완료 처리하지 않는다.

## 데이터와 인터페이스

promise_links, promises, participants, participant_sessions를 ERD대로 처음 도입한다. UUID PK/FK, invite_token·promise_link_id·session_token_hash UNIQUE, 약속별 normalized_nickname UNIQUE, role=host 조건부 UNIQUE, host는 active CHECK, ON DELETE RESTRICT를 포함한다. 약속 설정은 draft에서 NULL을 허용하고 상태별 필수값·confirmed_start_at·cancelled_at 제약은 DOC-002 §4.2를 따른다. 모든 시점은 Timestamptz(3), 일자는 Date, 일일 경계는 분 값으로 저장한다. 슬롯 테이블은 004에서 추가한다.

제안 인터페이스: 서버 전용 issueInviteLink(), 조회 readInvitation(inviteToken), Server Action registerHost({inviteToken,nickname,pin}), abandonDraft({inviteToken}). 브라우저가 보낸 role·participantId를 권한으로 사용하지 않는다. 응답은 성공 데이터 또는 사용자에게 복구 가능한 오류 코드이며 해시·DB 오류를 노출하지 않는다. 함수명·URL은 새 설계 제안이고 기존 미제공 API 명세를 재현한 것이 아니다.

공통 잠금·서버 시각·오류 계약·DB 테스트 기준은 [분해 계획](../spec-plan.md)의 공통 구현·검증 계약을 따른다. 참여자 인증이 필요한 경계에서는 서버가 약속 소속·세션·현재 역할·상태를 검사한다. 공개 링크 안내와 외부 챗봇은 각 경계의 공개 범위·호출 검증을 적용한다. 다른 참여자의 민감 정보를 오류에 포함하지 않는다.

## 구현 계획

초기 도메인 마이그레이션과 격리된 DB 테스트 기반 → 조회 부작용 방지 → 원자적 선점 → 세션 → 만료·나가기 순서로 각 동작의 RED/GREEN을 반복한다. 예정 파일은 apps/web/src/lib/invitation/, src/actions/invitation.ts, src/components/invitation/, src/app/p/[inviteToken]/, prisma/migrations/이며 모두 apps/web/ 아래에 둔다. 공통 잠금·세션 검증 경계는 후속 기능이 재사용한다.

한 동작의 실패 assertion을 실제 확인한 뒤 최소 구현·회귀 검증을 반복한다. 테스트 도구 오류나 DB 연결 실패는 RED로 인정하지 않는다.

## 확정 정책 — 2026-11-13

사용자가 닉네임·세션·링크 만료 정책과 닉네임 추가 기준을 확정했다. 아래 결정은 기존 원본에서 비어 있던 부분을 보완하며 제안이 아닌 구현·검증 기준이다.

- OPEN-01 확정: 앞뒤 공백 제거, NFC 정규화, 눈에 보이는 글자 단위 2~12자, 이모지 불허. 중간 공백은 유지한다. 정규화 중복 키에는 영문 대소문자 구분을 없애고 표시 이름에는 원래 대소문자를 보존한다. `Iris`와 `iris`는 같은 이름, `홍 길동`과 `홍길동`은 서로 다른 이름이다. 조합 방식만 다른 같은 한글은 동일하게 취급한다.
- OPEN-03의 001·002 범위 확정: 방장 등록부터 10분의 고정 초안 세션을 발급하고 설정 완료 시 응답 마감 후 7일까지 연장한다. 쿠키와 DB 세션 만료를 일치시킨다. 이후 마감 변경·재조율의 기존 세션 갱신 정책은 007에서 별도로 결정한다.
- OPEN-04 확정: KST 달력 3개월 후 같은 시각, 대상 날짜가 없으면 월말로 보정, 만료 시각부터 접근 차단. 예: 2026-01-31 15:00 KST 발급 → 2026-04-30 15:00 KST 만료. 기존 참여자·방장도 예외가 없으며 화면 문구는 정확히 “만료된 약속입니다”다.
- 만료는 서버의 조회·변경·재인증 경계에서 검사한다. 화면 숨김만으로 접근을 막았다고 판단하지 않는다. 기한이 남은 세션도 만료 링크를 우회하지 못하며, 이 정책은 후속 약속·결과 조회 기능에도 공통 적용한다.

## 결과

001 범위의 단위 6개·실제 DB 17개·브라우저 6개, 린트·타입 검사·빌드가 통과했다. 첫 검토의 zero-width·제어 문자, 만료 초안 삭제 권한, 없는·만료 링크의 해시 경계와 재검토의 U+2800 BRAILLE PATTERN BLANK, 선점 링크의 불필요한 scrypt를 각각 RED→GREEN으로 보완했다. [실행·검토 기록](../tdd/001-invitation-and-host.md)에 기존 구현과 각 검토·보완 근거를 구분했다.

2026-11-13 최종 요구사항 검토에서 AC-1~7과 실제 근거를 다시 대조했으며 새 중요 발견 없이 모두 충족으로 판정했다. 이어서 `feature 테스트`로 Docker Node.js 24의 단위 6개·격리 PostgreSQL 통합 17개·Chromium 6개·린트·타입 검사·운영 빌드를 다시 실행해 모두 종료 0을 확인했고, 사용자 완료 요청에 따라 같은 날 완료 처리했다.

AC-4의 모집 시작/세션 연장 실제 연결은 예정대로 002, AC-6의 재인증 연결은 003에서 검증한다. 현재 설정 페이지는 방장 인증 후 진입·경고·나가기까지이며 날짜·정원 입력 폼은 002 범위다. 카카오·Neon 운영 연결·배포는 수행하지 않았다.
