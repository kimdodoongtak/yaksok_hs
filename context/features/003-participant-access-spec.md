참여자는 계정 가입 없이 닉네임·PIN으로 약속에 참여하고 다른 기기에서도 본인 응답에 접근한다.

## 데이터와 인터페이스

participants·participant_sessions를 재사용하고 보안용 auth_attempts를 추가했다. Server Action은 joinPromise, loginParticipant, logoutParticipant, changeParticipantPin이며 inviteToken 바인딩·서버 쿠키와 FormData를 받는다. PIN 변경은 인증된 본인의 현재 PIN을 추가 검증한다. 인증 성공은 필요한 본인 정보만 반환한다. 조회는 서버 전용 접근 계층을 사용하고 비밀값을 클라이언트에 넘기지 않는다.

PIN 시도 제한은 PostgreSQL 보안용 테이블을 사용해 여러 서버 인스턴스가 공유한다. 제품 도메인 테이블과 구분하며 원자적 집계와 저장 이유는 아래 구현 설계에 기록했다. 실제 Vercel 배포 검증은 아직 수행하지 않았다.

공통 잠금·서버 시각·오류 계약·DB 테스트 기준은 [분해 계획](../spec-plan.md)의 공통 구현·검증 계약을 따른다. 참여자 인증이 필요한 경계에서는 서버가 약속 소속·세션·현재 역할·상태를 검사한다. 공개 링크 안내와 외부 챗봇은 각 경계의 공개 범위·호출 검증을 적용한다. 다른 참여자의 민감 정보를 오류에 포함하지 않는다.

## 구현 설계·후속 결정

003 제품 정책에 따라 구현했다. PostgreSQL `auth_attempts`를 보안용 공유 테이블로 추가했다. 계정 실패는 약속 행 잠금 안에서 집계하며 IP 예산은 카운터 행 잠금으로 직렬화한다. IP 예산은 모든 약속의 등록·로그인·PIN 변경 요청에 고정 10분 창당 30회를 허용하는 기술 방어값이며 성공도 포함한다. 이는 사용자 확정값인 약속·닉네임별 연속 5회/10분을 대체하지 않는다. 키는 해시로 저장하며 원문 PIN·IP를 저장하지 않는다. 계정 실패 행은 로그인 성공 시 삭제, IP 창은 기한 후 다음 요청에서 초기화한다. 만료된 전체 카운터의 정기 물리 정리 작업은 아직 없다.

Vercel 환경에서만 `x-vercel-forwarded-for`의 단일 유효 IP를 사용한다. 로컬·누락·이상값은 `unknown` 공유 제한을 적용하며 전달 헤더로 우회하지 못한다. [Vercel 공식 헤더](https://vercel.com/docs/headers/request-headers#x-vercel-forwarded-for)를 확인했으며 실제 배포는 미검증이다. Origin/Host와 요청 출처를 검사하고 변경은 Server Action에서만 수행한다.

PIN 변경은 로그인된 본인의 현재 PIN을 다시 검증하고 PIN 저장·모든 기존 세션 삭제를 한 트랜잭션에서 처리한다. 성공 후 새 PIN 재로그인 화면으로 연결한다. 오류 시 닉네임은 유지하고 PIN은 응답에 포함하지 않으며 입력란을 비운다.

OPEN-03의 마감 변경·재조율 세션 갱신은 007, OPEN-09의 수동 방장 위임은 008에서 정한다. 기존 비즈니스 규칙·API 문서는 미제공 상태다. 전체 결정 목록은 [분해 계획](../spec-plan.md)에 유지한다.
