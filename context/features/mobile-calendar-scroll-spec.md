# 모바일 시간표 오른쪽 스크롤 여백

- 상태: 완료 — 2026-11-16 (아래 후속 사용자 교정 포함)
- 근거: 모바일 오른쪽 하단에서 스크롤하려 하면 시간 칸이 선택된다는 사용자 제보.
- 범위: 시간표 오른쪽에 선택과 겹치지 않는 스크롤 여백을 확보한다. 기존 탭·드래그 선택과 왼쪽 시간축 스크롤은 유지한다.

## 수용 기준

1. 320px·393px 모바일 화면에서 오른쪽 끝으로부터 30px 안쪽, 시간표 하단에서 시작한 세로 제스처는 페이지를 스크롤하며 기존 선택을 바꾸지 않는다.
2. 마지막 요일을 포함한 시간 칸은 계속 탭·드래그로 선택할 수 있다. 날짜와 시간 칸의 열 정렬을 유지하며 가로 넘침이 없다.
3. 왼쪽 시간축 스크롤, 선택 중 가장자리 자동 스크롤, PC 마우스·키보드 입력, 제출은 유지한다.

## 검증

- AC1은 버그 수정 TDD 대상: Playwright 실제 터치 이벤트로 RED → GREEN을 확인한다.
- AC2의 기존 탭 선택과 AC3은 기존 동작 회귀, 열 정렬·반응형은 브라우저 배치 검사로 검증한다.
- Docker Node.js 24에서 관련 브라우저·단위 테스트, 린트·타입·빌드를 실행한다. DB 구조·서버 로직 변경은 없다.
- 실제 모바일 기기와 운영 배포 검증은 별도이며 로컬 Chromium 터치 에뮬레이션과 구분한다.

## 결과

- 오른쪽 스크롤 여백과 날짜 정렬을 구현했다. 320px 후보 캡션은 셀 여백·자간을 보완해 기존 영역 안에 표시한다.
- AC1의 실제 RED→GREEN, AC2·3 회귀와 단위·린트·타입·빌드를 확인했다. [TDD 실행 기록](../tdd/mobile-calendar-scroll.md).
- 커밋·푸시·운영 배포 및 실기기 검증은 수행하지 않았다.

## 후속 요청: 정보 접기와 중앙 정렬

사용자가 카톡 첫 진입의 작은 화면과 오른쪽 여백 추가 후 중심 불균형을 확인하고 두 가지 보완을 함께 요청했다.

- AC4: 900px 미만에서는 상단을 약속 정보 버튼·남은 마감 시간·방장의 응답 마감 버튼 한 줄로 줄인다. 로고·진행 단계·참여 정보는 기존 정보 패널에서 확인한다. 응답 마감 및 마감 후 후보 이동은 상단에서 바로 접근하며 참여자에게 마감 버튼을 노출하지 않는다.
- AC5: 정보 패널은 기본 닫힘이며 열기·닫기·Escape·참여자 선택 후에도 시간 선택과 스크롤을 보존한다. 데스크톱의 펼친 정보와 기존 마감 버튼은 유지한다.
- AC6: 시간축을 포함한 시간표 전체의 폭을 상단 보기 탭 및 하단 버튼 영역에 맞춘다. 시간표 내부의 오른쪽 빈 띠를 없애고 페이지 양쪽 바깥에 같은 폭의 스크롤 여백을 둔다. 시간 칸의 행 높이와 양옆 스크롤을 유지한다.
- AC7: 카톡 바가 차지한 공간을 고려한 320×640·393×640 콘텐츠 뷰포트에서 스크롤 전 기본 1시간 칸이 최소 네 행 완전히 보인다. 상단 정보·주 이동·날짜·제출은 스크롤 후에도 접근할 수 있다.
- AC4·5는 실제 브라우저 RED→GREEN, AC6·7은 배치 검수 및 회귀 검증으로 확인한다. 실제 카톡 WebView 검증과 로컬 높이 에뮬레이션을 구분한다.
- 후속 사용자 교정: 수치상 날짜 열 중앙 정렬보다 오른쪽 빈 공간이 큰 것이 문제라고 확인했다. 양옆 36px의 내부 여백안은 위 AC6으로 대체하고, 방장 마감 버튼도 패널 내부에서 상단으로 돌린다.
- 마감 액션 표현: 모바일 상단의 응답 마감은 큰 검정 캡슐 대신 작은 보조 텍스트로 표시한다. 버튼 의미·최소 44px 터치 높이·기존 확인창은 유지한다. 정적 스타일 보완이므로 시각 검수와 기존 마감 흐름으로 검증한다.
- 마감 후 후보 보기 링크는 사용자 요청대로 빨간 텍스트로 표시한다.

## 후속 최종 결과

- 상단 기본 접힘, 바깥쪽 보조 텍스트 마감 액션, 빨간 후보 보기, 시간표 전체 폭 정렬 및 양쪽 페이지 32px 스크롤 여백을 적용했다.
- 320×640·393×640 첫 진입에서 최소 네 행, 기존 드래그·제출·마감·정보 패널 회귀와 린트·타입·빌드를 확인했다. 상세 명령과 중간 실패·최종 통과는 TDD 기록에 구분했다.
- 약속 일정 정보의 2×2 표·정보 우선순위 시안은 사용자 결정으로 적용하지 않고 기존 정보 배치를 유지한다.
- 2시간 보기 높이는 이후 추가 요청에 따라 다른 보기와 동일한 50px로 통일했다.

## 추가 요청: 2시간 보기 높이 통일

사용자의 높이 축소 요청에 따라 모든 보기의 행 높이를 50px, 선택 칸 최소 높이를 44px로 통일한다. 시간 단위 전환 시 스크롤 위치 환산도 같은 행 높이를 사용한다. 2시간 후보 캡션은 짧아진 칸 안에 들어가도록 조정하고 기존 제출·부분 선택·후보 영역을 회귀 검증한다.

## 추가 요청: 마감 시간 중앙 정렬

방장·참여자 및 마감 전·후 상단의 남은 시간/마감 표시를 화면 중심에 맞춘다. 320·393·1280px에서 양쪽 조작과 겹치지 않고 스크롤 후에도 중심을 유지해야 한다. 기존 카운트다운 로직은 유지한다.

중앙 정렬 후 양쪽 간격도 같아 보이도록 모바일 정보·마감/후보 액션을 동일한 글자 크기·굵기로 맞춘다. 왼쪽 메뉴 아이콘을 유지하고 응답 마감에는 같은 크기의 체크 아이콘, 후보 보기에는 이동 화살표를 표시한다. 열기 동작과 터치 높이는 유지한다.

되돌리기·복구하기는 흰 배경을 없애고 회색 19px 아이콘과 가는 선으로 존재감을 낮춘다. 기존 클릭 영역과 동작은 유지한다. 정적 스타일 조정이므로 별도 RED 없이 기존 이력 동작 회귀와 화면으로 확인한다.

좌우 교체안은 사용자 요청으로 취소했다. 되돌리기·복구하기는 왼쪽, 시간 단위 선택(30분·1시간·2시간)은 오른쪽인 기존 순서를 유지한다.
