## 후속 오류 수정 — 2026-11-16

- 사용자 승인: 수정 커밋·푸시·운영 반영. 추가 제보: 방장·참여자가 제출한 뒤 모두 시간 정보를 불러오지 못한다.
- 운영 근거: `/availability/state`와 `/overview` GET의 반복 HTTP 503, DB 진단에서 공통 세션 검사 `SELECT ... FOR UPDATE OF p`의 transactionid 잠금 대기를 확인했다. 현재 코드는 실제 DB 예외를 일반 오류로 반환하므로 개별 실패의 내부 코드까지 확인된 것은 아니다.
- 범위 확장: 두 읽기 서비스만 약속 행의 배타 잠금을 제거하고 `RepeatableRead` 트랜잭션에서 권한·설정·슬롯을 같은 DB 스냅샷으로 읽는다. 쓰기 경로의 기본 잠금과 마감 판정은 유지한다. 시간 제한을 늘려 지연을 숨기지 않는다.
- TDD 대상 AC-1: 실제 DB의 별도 연결이 같은 약속에 미커밋 변경을 보유해도 방장·참여자의 본인 시간/전체 현황 조회가 대기하지 않고 마지막 커밋 상태를 반환한다. 취소 커밋 이후 새 조회는 거절한다.
- TDD 대상 AC-2: 한 조회 도중 제출이 커밋되어도 설정·버전·슬롯이 서로 다른 시점으로 섞이지 않는다. 다음 조회는 새 제출을 반환한다.
- 회귀 AC-3: 기존 권한·동시 제출·마감·취소 검증과 두 사용자 동시 제출 후 집계 흐름을 통과한다.
- 제품 테스트는 로컬 격리 DB에서만 실행한다. 운영 검증은 배포 지역·읽기 응답과 실제 사용자 요청 로그를 확인한다.
