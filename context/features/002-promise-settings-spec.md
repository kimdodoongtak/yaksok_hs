모집 시작 성공 직후에는 `초대 준비 완료` 도장이 한 번 찍히며, 링크 복사·새로고침·재접속 때 재생하지 않는다. 도장은 정적으로 남고, 동작 줄이기 설정에서는 처음부터 정적으로 표시한다. 링크 복사 성공은 기존 `복사했어요` 문구로 알린다. 티켓에 표시할 설정은 유효한 해당 약속의 active 방장 세션에만 반환하며 세션 없음·위조·타 약속·만료에는 반환하지 않는다. 링크 만료는 기존처럼 `만료된 약속입니다`만 표시한다. 친구의 참여·재인증은 003 범위를 유지한다. 저장 정보 조회와 최초 표시·재방문 동작은 AC-6·7의 통합/E2E TDD 대상이며 정적 장식은 시각 검수한다.

2단계는 기본 상태의 393×852 화면에서 헤더부터 모집 시작 버튼까지 한 화면에 보이도록 요약 높이와 간격을 제한한다. 입력 오류·글자 확대처럼 내용이 늘어나는 경우에는 내용을 자르지 않고 세로 스크롤을 허용한다.

방장 설정 화면 → 1/2 날짜·시간: 시작일 KST 오늘·종료일 달력 한 달 뒤·하루 09:00~24:00·소요 2시간을 요약 표시, 필요 항목 펼쳐 수정 → 다음 → 2/2 모집 설정: 정원 5명·응답 마감 시작일 7일 뒤 23:59와 이전 단계 요약 → 모집 시작 → collecting 표시와 초대 링크 복사. 이전·다음 이동은 입력을 유지하며 DB를 저장하지 않는다. 잘못된 값은 해당 단계와 편집기를 열어 안내하고 수정 후 재시도한다. 만료·권한 변경 시 최신 상태로 이동한다.

## 수용 기준

2026-11-14 검토 보완: 응답 마감을 직접 편집하기 전에는 유효한 시작일로 2단계에 진입할 때 시작일 +7일 23:59 기본값을 갱신한다. 직접 편집한 마감은 시작일 변경·이전/다음 이동·서버 오류 뒤에도 보존하고, 최종 유효성은 서버에서 검사한다.

하루 시간 범위는 시작·종료 값을 항상 표시하고 각각 오른쪽의 위·아래 화살표로 30분씩 조절한다. 토글·분 선택 버튼은 제거한다. 기존 시작 00:00~23:30·종료 00:30~24:00 경계를 유지하며 경계의 화살표는 비활성화한다. 소요 시간도 항상 표시하고, 사용자 제공 시계 이미지처럼 큰 두 자리 시·분 카드와 중앙 가로선·하단 단위로 표현한다. 예: `02` 시간 / `30` 분. 오른쪽 화살표 한 쌍으로 30분씩 조절한다. 키보드 조작과 오류 뒤 값 보존을 포함해 AC-3·7의 브라우저 TDD 대상이다.

2026-11-13 사용자 승인: 초기 설정은 `1/2 날짜·시간 → 2/2 정원·응답 마감` 두 단계로 진행한다. 날짜만 기본값을 요약하고 수정할 때 달력을 펼친다. 하루 시간 범위와 소요 시간은 바로 조절한다. 이전·다음 이동 시 모든 입력을 보존하며 다음은 저장·모집 시작을 수행하지 않는다. 1단계 오류는 이동 전에 안내하고 최종 서버 오류는 해당 단계로 돌아가 복구할 수 있게 한다. 날짜 오류는 달력을 펼친다. 최종 저장·권한·만료 검증은 서버에서 유지한다. AC-7의 단계 이동·입력 유지·오류 복구는 브라우저 TDD 대상이다.

## 데이터와 인터페이스

001의 promises 설정 필드를 사용한다. 저장할 필드: participant_limit, date_range_start/end, daily_start/end_minute, duration_minutes, voting_deadline_at, status. DB 제약은 ERD §4.2와 일치시킨다.

구현: Server Action `startCollection(inviteToken, state, formData)`에서 날짜는 YYYY-MM-DD, 시간은 HH:mm(종료만 24:00), 마감은 `datetime-local` 값을 KST로 해석해 서버 시점으로 변환한다. 변경 권한은 세션의 약속·host 여부로 확인한다. 입력 실패는 구조화된 필드 오류로 반환하고 제출값을 보존한다.

공통 잠금·서버 시각·오류 계약·DB 테스트 기준은 [분해 계획](../spec-plan.md)의 공통 구현·검증 계약을 따른다. 참여자 인증이 필요한 경계에서는 서버가 약속 소속·세션·현재 역할·상태를 검사한다. 공개 링크 안내와 외부 챗봇은 각 경계의 공개 범위·호출 검증을 적용한다. 다른 참여자의 민감 정보를 오류에 포함하지 않는다.

## 구현 계획

설정 검증 공개 함수 → 서버 변경·잠금 → 모집 폼·달력·링크 복사 순서로 구현한다. 예정 apps/web/src/lib/promise-settings/, src/actions/promise-settings.ts, src/components/promise-settings/. 해석되지 않은 제품 경계를 테스트 기대값으로 먼저 고정하지 않는다.

한 동작의 실패 assertion을 실제 확인한 뒤 최소 구현·회귀 검증을 반복한다. 테스트 도구 오류나 DB 연결 실패는 RED로 인정하지 않는다.

## 미정 사항

002 구현을 막는 OPEN 항목은 없다. 정원 2~30과 30분 단위는 ERD 기준으로 확정했고 OPEN-05·06도 구현에 필요한 범위에서 확정했다. 이후 마감 변경·재조율 때 기존 세션 만료를 갱신하는 정책은 007 구현 전에 별도로 결정한다.

OPEN 항목의 제안은 [분해 계획](../spec-plan.md)에 있으며 사용자 확정 전 제품 규칙으로 고정하지 않는다.
