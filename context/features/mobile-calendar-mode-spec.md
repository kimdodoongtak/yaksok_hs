# 모바일 시간표 스크롤·선택 전환

- 상태: 완료 — 2026-11-20 (버튼 방식 적용·검증, 사용감 확인 단계)
- 근거: 친구 테스트에서 여백 스크롤만으로 오선택이 해결되지 않았다는 제보. 사용자가 1번부터 변경을 요청했으며 버튼 전환과 첫 터치 활성화를 비교 중이다. 우선 명시적 버튼 전환을 적용해 사용감을 확인한다.
- 범위: 터치 기기의 내 시간표 조작. 날짜 전체 선택·입장 안내·최소 약속 시간은 이번 범위에서 제외한다.

## 수용 기준

1. 첫 진입과 새로고침은 스크롤 상태다. 시간 칸을 탭하거나 세로로 밀어도 선택·편집 이력이 바뀌지 않으며 페이지가 스크롤된다.
2. 고정 조작 영역의 `스크롤 / 선택` 버튼으로 전환한다. 선택 상태에서는 기존 탭·드래그 선택과 해제·가장자리 자동 스크롤을 유지한다. 선택 상태는 손을 떼어도 유지하며 스크롤 버튼으로 명시적으로 종료한다.
3. 스크롤로 전환해도 이미 고른 값과 되돌리기 이력을 보존한다. 제출 성공 또는 다른 보기로 전환하면 스크롤 상태로 돌아간다. 조회·제출 실패로 선택값을 잃지 않는다.
4. 전체 시간·다른 참여자·마감 뒤에는 선택 전환을 제공하지 않는다. PC 마우스·키보드는 기존 조작을 유지한다. 터치 지원 여부에 따라 전환 버튼을 표시한다.
5. 320·393px 터치 화면에서 가로 넘침 없이 상태를 구분하고 스크롤 뒤에도 버튼에 접근한다. 기존 좁은 화면 네 행 표시와 날짜 정렬을 회귀 확인한다.

## 검증

- AC1~3: Playwright Chromium 실제 터치 이벤트로 동작별 RED→GREEN. 기존 탭·드래그·제출 테스트에는 명시적 선택 모드 진입을 추가한다.
- AC4: 기존 마우스·키보드·읽기 전용 회귀 및 전환 버튼 노출 검사.
- AC5: 정적 스타일은 TDD 비대상. 실제 브라우저 캡처·배치 검수.
- Docker Node.js 24의 관련 브라우저 테스트·단위·린트·타입·빌드. 서버·DB 정책은 변경하지 않는다. 실기기 Safari·카카오톡 WebView 및 운영 배포는 별도다.

## 결과

- 터치 기본 스크롤, 고정 전환 버튼, 선택값·편집 이력 보존 및 제출/보기 전환 후 복귀를 구현했다.
- Docker Node.js 24: 관련 Chromium 52개·단위 46개·린트·타입·빌드 통과. 320·393px 화면을 검수하고 로컬 서버를 복구했다.
