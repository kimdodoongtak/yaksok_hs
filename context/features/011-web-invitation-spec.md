# 011 홈에서 약속 만들기

- 상태: 완료 — 2026-11-16
- 근거: 2026-11-16 사용자가 “홈에 ‘약속 만들기’ 버튼 추가 — 웹에서 바로 시작”을 선택했다. 001·010의 웹 생성 제외 범위는 이 추가 스펙으로 변경한다. 카카오 연동은 별도 후속이다.
- 목적: 공개 웹 방문자가 직접 링크를 발급받고 기존 방장 등록·설정·초대 흐름을 시작한다.

## 수용 기준

1. 홈 조회만으로 데이터를 만들지 않는다. ‘약속 만들기’를 명시적으로 누르면 서버에서 난수 링크를 발급하고 `/p/<token>` 방장 등록 화면으로 이동한다. 기존 001의 링크 만료·방장 선점·PIN·세션 정책을 유지한다.
2. 방장 등록 → 설정 → 모집 시작 → 링크 복사 → 다른 브라우저 참여로 이어진다. 홈 안내는 생성과 초대 링크 참여를 구분한다.
3. 처리 중 버튼 비활성화·‘만드는 중…’ 표시, 저장 실패 시 비밀값 없는 재시도 안내를 제공한다. 성공 이동을 오류로 잡지 않는다.
4. 동일 출처 POST만 허용하고 기존 DB 요청 제한기를 생성 전용 키로 재사용한다(접속 주소별 10분 30회, 인증 요청 예산과 분리). Vercel 신뢰 헤더 외에는 `unknown` 공통 예산을 사용한다. 제한·DB 장애 시 발급하지 않는다.
5. 기존 빨강 티켓 스타일과 키보드 접근을 유지하며 320·393·1280px에서 확인한다.

## 구현·검증 범위

- 홈 Client form → Server Action → 기존 `issueInviteLink` 서비스. 새 의존성·스키마·마이그레이션은 필요 없다.
- TDD: AC1·2 브라우저와 실제 `sdd_test` DB, AC3·4 서버 진입점 단위 테스트 및 오류 UI 브라우저. 기존 발급·요청 제한의 DB 회귀를 실행한다.
- 스타일·문서(AC5)는 TDD 비대상이며 실제 화면으로 검수한다. 새로고침·별도 요청의 전역 중복 제거는 범위에 없으며 처리 중 버튼으로 연타를 막는다.
- 모든 테스트는 Docker Node.js 24, 기존 보호된 `sdd_test` 실행기를 사용한다. Neon 운영 DB에 테스트를 실행하지 않는다.
- 린트·타입·빌드, 관련 초대·설정·참여 브라우저 회귀를 수행한다. 커밋·푸시·운영 배포는 이번 기능 선택에 포함하지 않는다.
- 기록: [011 TDD](../tdd/011-web-invitation.md).

- 구현 참고: [Next.js 공식 폼·Server Action 안내](https://nextjs.org/docs/app/guides/forms)의 `useActionState`와 처리 중 상태 패턴을 적용한다.

AC1~5 충족. Docker Node.js 24에서 단위 43개·관련 DB 32개·관련 브라우저 20개, 모바일 줄바꿈 보완 후 새 홈 2개 재검증, 최종 린트·타입 검사·빌드 통과. 320·393·1280px 검수 완료. 이번 변경은 로컬 구현이며 커밋·푸시·Vercel 배포는 수행하지 않았다.
