# 모바일 시간표 오른쪽 스크롤 충돌 — 2026-11-16

- 제보: 오른쪽 하단에서 손가락으로 스크롤하려 하면 시간 칸이 선택됨.
- 원인: 셀의 `touch-action: none`과 즉시 시작하는 드래그 선택은 기존 시간 입력 기능이다. 왼쪽 시간축만 충분한 스크롤 영역이 있고 오른쪽에는 페이지 여백 12~16px만 있었다.
- 수정: 900px 미만 화면에서 시간표와 날짜 열에 동일한 오른쪽 여백 28px를 추가했다. 총 40~44px의 여백에서 시작한 터치는 버튼에 닿지 않아 브라우저의 기본 스크롤로 처리된다. 기존 드래그 처리·마지막 요일 셀·제출 로직은 유지하고 안내 문구를 양옆 여백으로 변경했다.
- 재현: 320·393px에서 오른쪽 끝 30px 안쪽을 위로 밀었을 때 의도하지 않은 네 칸 선택을 확인했다. 실제 실행 결과는 [TDD 기록](../tdd/mobile-calendar-scroll.md)에 남긴다.
- 회귀 보완: 320px의 후보 시간 범위가 줄바꿈되지 않도록 읽기 전용 칸의 여백과 정시 범위의 자간을 조정했다. 기존 터치 테스트는 관성 스크롤을 탭으로 멈춘 뒤 다음 제스처를 시작하도록 준비 단계를 수정했다.
- 검증: 오른쪽 스크롤 RED→GREEN, 기존 모바일 선택과 후보 전체 회귀, 단위 43개·린트·타입·빌드 통과.
- 한계: 여백 밖 시간 칸에서 시작한 드래그는 기존처럼 시간을 선택한다. 실제 휴대전화·Vercel 반영 확인은 별도다.

## 후속 사용자 교정 반영

- 기존의 내부 오른쪽 28px 여백 및 시도했던 양옆 36px 안은 최종 배치에서 제거했다. 시간축을 포함한 시간표 전체를 위 탭·아래 버튼 영역과 정렬하고 페이지 양쪽에 32px 여백을 둔다.
- 빈 여백 터치를 근처 시간 버튼으로 보정하는 브라우저 동작 때문에 접근성 트리와 키보드에서 제외한 여백 터치 표면을 추가했다. 표면은 기본 세로 스크롤을 허용하며 시간 선택을 시작하지 않는다.
- 모바일 상단은 정보 열기·남은 시간·방장 마감으로 줄인다. 로고·진행 단계·참여 상태는 기존 정보 패널에서 확인한다. 마감은 작은 보조 텍스트, 마감 후 후보 보기는 빨간 텍스트로 표시한다.
- 정보 패널의 약속 일정 설명은 기존 배치를 유지한다. 두 이미지 시안은 적용하지 않았다. 2시간 보기 높이도 기존 설정을 유지한다.
- 최종 관련 검증: 전체 47개 실행에서 45개 통과 후 여백 보완 및 터치 시나리오 분리, 영향 범위 8개 재통과. 단위 43개·린트·타입·빌드 통과. 아직 커밋·푸시·운영 배포하지 않았다.

## 추가 높이 축소

사용자 후속 요청으로 2시간 보기도 행 50px·칸 최소 44px로 줄였다. 단위 전환 스크롤 계산과 후보 캡션을 함께 조정했다. 실제 검증 및 간헐 회귀 실패는 TDD 기록 참조.
