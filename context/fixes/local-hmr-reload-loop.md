# 로컬 개발 서버의 반복 새로고침 복구

2026-11-25. 사용자가 5인 제출 완료 데모 링크를 열자 페이지가 계속 새로고침된다고 보고했다.

## 재현·진단

- Docker 개발 서버는 하나만 실행 중이었다. 로그인 전 페이지와 기존 약속 후보 화면 모두 요청·재컴파일이 반복됐다.
- `http://localhost:3000`을 컨테이너 Chromium에서 열어 10초 관찰: 메인 프레임 이동 18회, HMR WebSocket의 `turbopack-message`에 `type:restart` 반복. 로그인/후보 간 리다이렉트 루프가 아니라 개발 서버가 전송한 자동 갱신이었다.
- 같은 시간 `src`, `next-env.d.ts`, `tsconfig.json`, `next.config.ts`, `.next-browser` 파일 감시에서는 변경이 없었다. 구체적인 캐시 이상 발생 계기는 확정하지 않았다.
- `127.0.0.1`로 연 첫 진단은 개발 서버의 origin 차단 때문에 WebSocket이 연결되지 않아 실제 localhost 재현을 대신하지 못했다. localhost로 바꿔 재현했다.

## 조치

- 확인한 `next dev` 프로세스만 종료했다. `.next/dev`를 같은 캐시 볼륨 안의 `dev-before-reload-*`로 이동해 백업하고, 동일한 `npm run dev`·호스트 포트 3001로 다시 시작했다.
- 약속·제출 데이터, 사용자 세션, 제품 코드와 운영 서비스는 변경하지 않았다. 환경 복구이므로 제품 기능 TDD 대상은 아니며 실제 브라우저 재현 전후를 비교한다.

## 검증

- 재시작 후 반복 재컴파일이 멈추고 기존 약속의 정상 5초 폴링만 남았다.
- 첫 확인 스크립트는 로그인 후 후보로 자동 이동한다고 잘못 가정해 시간 초과됐다. 실제 동선은 로그인 → 참여 정보 → `시간 후보 보기`여서 해당 동선으로 수정했다. 로그인 자체는 성공했으며 이를 제품 실패로 처리하지 않는다.
- 최종 Chromium 확인 종료 0: 로그인 폼 8초 동안 이동/입력 초기화 없음, 로그인 후 후보 화면 12초 동안 이동/명단 닫힘 없음, HMR restart 0회, 페이지 오류 0개. 기본 후보 5개·첫 후보 참석 명단 5명·더 보기 후 7개 확인. 실기기 Safari는 미검증. 커밋·배포 없음.
