# 운영 생성·제출 지연과 시간 정보 조회 실패

- 증상: 배포 사이트에서 초안·링크 생성·제출에 약 6~7초가 걸린다는 사용자 제보.
- 발견: Vercel 함수는 미국 동부 `iad1`, Neon DB는 싱가포르 `aws-ap-southeast-1`. 여러 순차 DB 요청이 지역 간 왕복을 반복한다.
- 추가 증상: 방장·참여자가 제출한 뒤 모두 시간 정보 조회 실패. 운영 `/overview`·`/availability/state` GET의 반복 503을 확인했다.
- 추가 발견: 공통 세션 검사가 조회에도 `FOR UPDATE`를 사용해 자동 갱신이 같은 약속의 쓰기와 잠금 경쟁을 한다. Neon 읽기 전용 진단으로 실제 잠금 대기를 확인했고 로컬 독립 DB 연결로 재현했다. 운영 예외의 내부 코드는 기존 catch 처리 때문에 확인하지 못했다.
- 조치: `apps/web/vercel.json`에 `regions: ["sin1"]`을 명시하고 두 조회 서비스만 배타 잠금 없는 `RepeatableRead`로 변경한다. 권한·설정·슬롯은 같은 스냅샷에서 읽고 쓰기의 잠금·마감·원자성을 유지한다.
- 검토: 조회 중 취소가 미커밋이면 마지막 커밋 상태를 반환하며, 취소 커밋 뒤 새 조회는 차단한다. 조회 도중 변경이 커밋되어도 이전 설정과 새 슬롯을 섞지 않는다. 반복 조회가 쓰기를 막지 않으며 다른 서비스의 쓰기 경로는 기본 잠금을 유지한다.
- 적용 상태: 로컬 수정·단위 43개·DB 93개·브라우저 42개·린트·타입·빌드 통과. 운영 반영 확인 진행 중.
- 근거: [스펙](../features/performance-region-spec.md), [측정·검증](../tdd/performance-region.md).
