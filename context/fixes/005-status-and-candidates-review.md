## 발견사항

- 문서 경미 불일치: API 설명이 overview와 별도 본인 편집 조회의 필드를 혼용했다. 실제 응답에 맞춰 설명을 정리했다.
- 문서 경미 불일치: 변경 과정의 후보 상세 창·시간 배지·개별 원형 말풍선 기록이 현재 요구사항으로 읽힐 수 있었다. 이력은 보존하고 최신 결정이 앞선 결정을 대체한다는 기준을 추가했다. 사용자가 승인한 최종 UI를 새 디자인 문제로 보고하지 않는다.
- 후보 계산/인증/마감의 실제 RED→GREEN 기록과 사후 회귀·시각 검수를 구분했다. 테스트의 교집합 예제는 독립 기대값이며 실제 DB 검증을 mock으로 대체하지 않는다. 후보 테스트에 skip/todo는 없다.
- 서버 전용 DB 경계, 쿠키 기반 동일 약속 인증, 현재 역할 검증, 조기 마감 동일 출처 검사, private/no-store 응답을 확인했다. PIN 해시·세션·타인 제출 메타데이터를 overview에 포함하지 않는다.

## 검증과 제한

- 이번 검토 실행: 관련 단위 4개, 실제 PostgreSQL 통합 7개, 후보 Chromium 8개 모두 exit 0. 실행 근거는 [TDD 기록](../tdd/005-status-and-candidates.md).
- 제품 코드 변경이 없으므로 직전 최종 UI의 린트·타입·운영 빌드 통과 근거를 유지하며 이번에 재실행했다고 보고하지 않는다.
- 최대 범위 단일 조회: 30명×90일×48슬롯, 399.5ms·78,678bytes. overview는 같은 약속 행의 잠금을 잡고 전체 기간을 계산하므로 이 값만으로 30명 동시 폴링 성능을 보장할 수 없다. 동시 부하·운영 성능 목표는 기존 OPEN-11로 남기며 확인된 기능 결함으로 단정하지 않는다.
- 실제 iPhone Safari·Neon/Vercel·동시 다중 사용자 부하 미검증. 현재 결과는 검토 통과이며 전체 프로젝트 최종 회귀/기능 완료/배포 완료를 뜻하지 않는다.
