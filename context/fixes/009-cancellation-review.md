## R1 · P3 · 방장 취소 완료 화면에서 이후 링크 만료 안내가 갱신되지 않음

- 위치: `apps/web/src/components/participants/participants-panel.tsx:42`, `:75`, `:95`.
- 조건: 방장이 참여자 관리 화면에서 명시적으로 취소하고 그 화면을 계속 열어둔 동안 링크 유효기간이 끝난다. 만료 직전 취소 후 탭을 나중에 다시 열어도 같은 조건이다.
- 재현: 테스트 전용 약속을 생성하고 방장으로 `/participants`에 접속 → ‘약속 취소’ 확인 → 취소 안내 확인 → 해당 테스트 링크의 발급 시각만 100일 전으로 옮겨 서버 만료 조건 재현 → 공개 `/state`의 `{state:"expired"}` 확인 → visibilitychange 및 기존 5초 폴링보다 긴 7초 대기.
- 실제: ‘만료된 약속입니다’ heading을 찾지 못해 assertion 실패(exit 1). 브라우저 DOM에는 ‘취소된 약속입니다.’ heading만 남았다. 재현은 기존 제품 로직을 mock하지 않고 테스트 DB의 자기 링크 시각만 조정했다.
- 원인: 취소 callback이 `finished.current=true`, `cancelled=true`를 설정하고 effect가 `cancelled`에서 polling과 visibilitychange 구독을 모두 중단한다. 자체 취소 heading만 렌더링하며 공개 상태 조회를 이어가지 않는다. 초안/초대 페이지의 `LiveInvitation`은 취소 뒤에도 최소 공개 조회를 유지하므로 경로별 동작이 다르다.
- 영향: 취소·접근 차단·보존 데이터는 정상이며 정보 노출은 없다. 새로고침하면 서버의 올바른 만료 판정을 받지만 열린 화면은 AC-4의 안내 우선순위와 불일치한다.
- 보완 방향: 취소 즉시 상세 내용을 숨긴 상태를 유지하면서 공통 공개 안내 화면으로 연결하거나 최소 공개 상태 조회를 계속한다. 상세 조회를 복구하거나 이전 성공 응답으로 상세 화면이 다시 나타나게 해서는 안 된다.
- 후속 검증: 취소 → 링크 만료의 열린 화면 전환을 영구 회귀 테스트로 추가해 RED→GREEN을 확인하고 기존 초안 취소·늦은 조회·응답 유실 재시도를 재검증한다. 이번 검토에서는 수정·GREEN을 수행하지 않았다.

## TDD·설계 점검

- 신규 권한·취소 전이·HTTP 계약·UI 연결·늦은 조회 경계의 실제 RED/GREEN 기록을 확인했다. 008 트랜잭션 재사용의 롤백·경쟁과 기존 서비스 차단은 사후 테스트로 구분한다.
- DB 테스트는 전용 PostgreSQL과 독립 연결·동시 시작 장벽을 사용한다. 실제 트랜잭션을 mock하지 않는다. 상태별 전체 보존 행 비교는 ERD 보존 규칙의 관찰 결과다.
- 브라우저의 네트워크 차단·지연은 실패·응답 유실 재현용이며 서버 취소 처리는 실제로 실행한다. skip/only로 검증을 회피한 테스트는 없다.
- Server Action은 쿠키 세션·동일 출처를 검증하고, 서버용 DB/보안 모듈을 클라이언트에 노출하지 않는다. 공개 응답에는 취소/만료 상태만 반환한다.
- 스키마·의존성 추가, 복원·자동 데이터 삭제·수동 위임 등 스펙 밖 기능은 없다. 현재 기능의 문서 띄어쓰기를 정리하고 검토 결과를 연결했다.
