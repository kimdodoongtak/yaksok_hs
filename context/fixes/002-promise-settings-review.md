# 002 검토 — 시작일 변경 후 응답 마감 기본값 미갱신

## 환경과 증상

2026-11-14 `feature 검토`. 기준 `main`, HEAD `62f7f91`과 현재 미커밋 002 구현을 검토했다. `.vscode/`는 사용자 변경으로 제외했다. 제품 코드와 테스트 파일은 수정하지 않았다.

**P2 · AC-5 부분 충족:** 시작일을 수정하고 처음 2단계에 진입해도 응답 마감은 최초 화면 진입일 +7일로 남는다. 사용자가 마감을 직접 입력하지 않은 상태에서도 선택한 시작일 +7일 기본값이 반영되지 않는다. 모집 시작 서버 검증은 이 값을 미래의 유효한 마감으로 받아들일 수 있어 의도한 기본값보다 일찍 모집을 마감하게 된다.

## 재현

Docker Node.js 24·Chromium·격리 `sdd_test`에서 임시 브라우저 확인 스크립트를 실행했다. 저장소 소스/테스트 파일은 만들거나 수정하지 않았고 검토용 링크·약속·참여자·세션은 종료 시 삭제했다.

1. 2026-11-14 KST에 새 링크에서 방장 등록.
2. 1단계 날짜를 시작 2026-11-28, 종료 2026-12-24로 변경.
3. `다음`으로 처음 2단계에 진입. 응답 마감은 직접 수정하지 않음.
4. 실제: `2026-11-21T23:59`. AC-5 기대: `2026-12-05T23:59`.

스크립트 종료 0, 비교 출력 `matches:false`. 이는 관찰용 재현 결과이며 자동 회귀 테스트 통과 또는 수정의 GREEN 근거가 아니다.

## 원인과 수정 범위

- `apps/web/src/lib/promise-settings/policy.ts`의 `defaultPromiseSettings`는 최초 서버 시각의 오늘 +7일을 계산한다.
- `apps/web/src/components/promise-settings/settings-form.tsx`의 `next()`는 날짜를 읽어 요약만 갱신한다. 마감 input은 `defaultValue={state.values.votingDeadline}`를 사용해 처음 마운트한 값을 유지한다.
- 수정 방향: 사용자가 아직 마감을 직접 수정하지 않았다면 선택 시작일 +7일 23:59로 갱신한다. 직접 설정한 마감은 이전·다음 이동이나 시작일 변경으로 덮어쓰지 않는다. 유효성은 기존 서버 정책으로 최종 검증한다.

## 실제 결과와 제한

- 이번 실행: Docker `npm run test` 종료 0, 4파일 11개 통과. 위 기본값 불일치는 기존 테스트가 선택 시작일 변경과 미편집 마감의 관계를 검사하지 않아 잡지 못했다.
- 직전 동일 코드 검증 근거 재사용: 격리 DB 22개·Chromium 8개·린트·타입 검사·운영 빌드 종료 0. 이번 검토에서는 전체 검증을 재실행하지 않았다.
- TDD 기록에서 실제 RED→GREEN과 정적 시각 검수, 첫 실행부터 통과한 사후 회귀를 구분한 것을 확인했다. 특히 서비스 권한·롤백·경쟁 일부는 사후 회귀이며 모두 개별 RED를 거쳤다고 주장하지 않는다. 새 수정은 재현 실패 테스트부터 진행한다.
- 서버/클라이언트 경계, 세션 해시와 비밀값 미노출, 기존 마이그레이션의 제약조건, 새 의존성/운영 변경 없음도 확인했다. 미구현 003 친구 참여·006 확정 티켓은 이번 결함에 포함하지 않는다.
- 결론: **검토 중, 완료 보류**. 확인한 P2를 보완하고 관련 회귀와 최종 검증 후 완료 가능 여부를 다시 판단한다.
