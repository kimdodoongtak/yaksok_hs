# 프로젝트 개요

## 서비스 정의

- 서비스 이름: 약속 잡기 도우미.
- 고객: 대학생 스터디·동아리, 친구 모임, 소규모 회식 등 주로 3인 이상 모임의 주최자와 참여자. 서비스 정원은 ERD 기준 방장 포함 2~30명이다.
- 문제: 여러 사람의 날짜·시간을 모으고 최종 일정을 정하는 과정이 분산되어 조율 부담이 크다.
- 가치: 웹에서 약속을 만들고 초대 링크로 계정 가입 없이 참여해 시간 입력부터 후보 추천·방장 확정까지 한 흐름으로 진행한다. 2026-11-16 사용자 선택으로 웹 생성 진입점을 추가하며 챗봇 연동은 후속 010 범위다.
- 첫 검증: 실제 그룹의 시범 사용으로 생성·공유 준비 3분 이내, 생성~확정 완료율 80% 이상, 만족도 평균 4.0/5 이상을 확인한다. 아직 측정하지 않았으며 표본·기간은 미정이다.
- 최소 기능: 초대 링크, 닉네임·PIN 등록과 재인증, 약속 설정, 30분 가능 시간 제출·재제출, 후보 추천, 수동 확정·링크 공유, 재설정·재조율, 탈퇴·내보내기·방장 승계, 취소.
- 범위 밖: 회원·카카오 로그인, 장소·위치·투표, 톡캘린더, 자동 알림, AI, 반복 모임 이력·정산·예약·길찾기·회원 채팅, 3단계 시간 입력, 최소 인원 설정.
- 운영: MVP의 취소·탈퇴 데이터는 자동 삭제하지 않으며 ERD의 삭제 예외를 적용한다. 비용·고객 지원 책임과 장기 운영 보관 정책은 별도 결정 대상이다.

## 원본 자료 해석 기준

- 2026-11-05 사용자 결정: [PRD](inputs/prd.md)와 [ERD](inputs/ERD.md)가 충돌하면 ERD를 우선한다. PRD 안의 비즈니스 규칙 우선 문구보다 이번 사용자 결정을 우선 적용한다.
- 현재 제공된 기준 자료는 PRD, ERD(문서상 작성일 2026-09-23), [Figma 참고 이미지](inputs/피그마.png)다. 이미지에서 확인한 범위만 디자인 근거로 사용한다.
- 비즈니스 규칙과 API 명세는 사용자가 별도로 작성했으나 아직 제공하지 않았다. 미작성으로 간주하거나 내용을 추정하지 않고, 미제공·미확인으로 기록한다. 해당 자료 없이도 현재 자료로 기능 스펙 초안을 작성할 수 있다.
- ERD에 없는 내용은 충돌하지 않는 PRD 요구사항으로 보완한다. 어느 자료에서도 정할 수 없는 제품 결정은 스펙의 미정 사항으로 남긴다. 서로 다른 제한 조건은 자동으로 충돌로 간주하지 않는다.
- 이 기준에 따라 참여 정원은 방장 포함 2~30명, 일정 확정은 방장 수동 선택, MVP의 취소·탈퇴 데이터는 자동 삭제하지 않는 설계를 따른다. draft 정리 등 ERD에 명시된 삭제 예외는 별도로 적용한다.
- 기술 스택·배포 환경은 아래 프로젝트 기술 결정을 유지한다. 원본 자료의 정책과 실제 구현·검증 상태는 구분한다.
- 2026-11-06: 제공 자료 전체의 [분해 계획](spec-plan.md)과 [기능별 스펙 목록](new-feature-list.md)을 작성했다. 비즈니스 규칙·기존 API 원본과 Figma 원본은 미제공으로 유지하며 문서 생성만으로 구현 완료로 보지 않는다.

## 기술 결정

| 항목 | 기준 |
| --- | --- |
| 구조 | 하나의 Next.js 16 App Router 풀스택 앱 |
| UI | Next.js 안의 React 컴포넌트, Tailwind CSS 4 |
| 언어 | TypeScript 5, 엄격한 타입 검사 |
| 런타임 | Node.js 24, DB를 사용하는 서버 코드는 Node.js 런타임 |
| 데이터 | Prisma 7 + PostgreSQL |
| 운영 | Vercel + Neon PostgreSQL |
| 로컬 | Docker Desktop의 Node.js 24 + PostgreSQL 17 |

별도 NestJS API 서버나 React SPA는 구성하지 않는다. 화면 조회는 Server Component, 앱 내부 변경은 Server Action, HTTP 계약이 필요한 요청은 Route Handler를 기본으로 한다. 상세 경계는 `docs/architecture.md`를 따른다.

## 확정된 제품 기준과 남은 결정

약속별 닉네임·숫자 4자리 PIN, 기기별 세션, host/member 권한, Asia/Seoul, 30분 슬롯, 전원 제출과 무관한 기한·조기 마감, 공통 참석자 2명 이상 후보, 방장 수동 확정은 원본에 정의되어 있다. 후보는 소요 시간 전체의 공통 참석자 수 내림차순·시작 시각 오름차순으로 정렬하고 상위 5개를 기본 표시한다.

2026-11-13 사용자 결정으로 닉네임은 trim·NFC 후 눈에 보이는 글자 기준 2~12자·이모지 금지·영문 대소문자 중복 구분 없음·내부 공백 유지로 확정했다. 초안 세션은 방장 등록부터 10분, 설정 완료 시 응답 마감 후 7일까지 연장한다. 링크는 KST 발급 시각의 달력 3개월 뒤 같은 시각(없는 날짜는 월말 보정)에 만료되며 기존 방장·참여자도 접근을 막고 “만료된 약속입니다”만 표시한다. 약속 설정의 시작일은 KST 오늘부터 허용하고, 종료일은 KST 오늘의 달력 3개월 뒤 이내(같은 일자가 없으면 월말 보정)이면서 시작~종료 양끝 포함 최대 90일이어야 한다. 설정 기본값은 정원 5명, 시작일 오늘, 종료일 달력 한 달 뒤, 하루 09:00~24:00, 소요 2시간, 응답 마감은 2026-11-16 변경 결정에 따라 오늘 7일 뒤 23:59 KST다. 마감은 오늘 기준 1주/2주 뒤 또는 직접 날짜를 선택하며, 신규 선택의 마감 시각은 23:59로 고정한다. 하루 시작·종료·소요 시간은 오른쪽 화살표로 ±30분씩 바로 선택하고 소요 시간은 두 자리 시·분 플립 시계 형태로 표시하며, 마감 뒤에도 약속 소요 시간 전체가 들어가는 30분 경계 시작 시각이 최소 하나 남아야 한다. 이후 마감 변경·재조율 세션 갱신, 공유 결과 공개 범위와 실제 카카오 계약 등은 분해 계획의 남은 OPEN 항목이다. 각 기능 구현 전에 필요한 항목만 확정한다. 요금제·결제·메일·파일 저장소는 MVP 요구사항으로 추가하지 않는다.

2026-11-14 사용자 결정으로 같은 약속·정규화 닉네임에서 PIN 연속 5회 실패 시 5번째 실패부터 10분 차단하며 로그인 성공 시 실패 횟수를 초기화한다. 차단 중 재시도로 종료 시각을 연장하지 않는다. 현재 PIN을 아는 본인만 PIN을 변경할 수 있고, 재로그인 세션은 성공 시각부터 7일간 유지한다. 기존 초기 세션·설정 완료 시 연장 정책은 유지한다. 유효 링크의 취소 안내는 인증 부재·만료보다 우선하며 로그인 없이 취소 사실만 보여준다. 링크 자체 만료는 여전히 최우선이다. 닉네임·PIN 찾기는 제외 쪽 검토 의견으로 남기고 기존 복구 없음 범위를 유지한다. 상세 결정과 구현 전 설계 항목은 [003 스펙](features/003-participant-access-spec.md)에 있다.

## 현재 상태

프로젝트 루트에는 스펙·스킬·문서와 Docker 구성을 두고, 개발 소스·DB 스키마·앱 설정은 `apps/web/`에 모은다. 같은 템플릿 모음의 다른 템플릿과 개발 파일을 공유하지 않는다.

문서·스킬·개발 환경 설정과 제품 스펙 초안 10개가 준비되어 있다. 2026-11-12 `000-project-bootstrap`의 최소 시작 화면과 서버 전용 Prisma 연결 모듈을 구현하고 Docker 기반 대체 검증을 마쳤다. 2026-11-13 요구사항 검토와 최종 검증을 마쳤고 문서 불일치를 정리했다. 같은 날 사용자 완료 요청에 따라 000 앱 기반을 완료 처리하고 이력을 남겼다. 이후 001 초대·방장 등록을 TDD로 구현하며 링크·약속·참여자·세션 모델, 마이그레이션과 단위·DB·브라우저 테스트를 추가했다. 두 차례 검토 발견사항을 RED→GREEN으로 보완하고 최종 요구사항 검토와 전체 회귀 후 2026-11-13 완료했다. 실행 근거는 [000 검증 기록](tdd/000.md), [001 TDD 기록](tdd/001-invitation-and-host.md), 작업 상태와 완료 이력은 [현재 기능](current-feature.md)에서 관리한다.

2026-11-14에는 002 약속 설정·모집 시작을 완료했다. 2단계 설정, 입력 정책, 원자적 모집 시작·세션 연장, 초대 티켓·링크 복사를 구현했고 기본 마감 갱신 검토 발견사항을 보완했다. 단위 12개·실제 DB 22개·Chromium 9개·린트·타입·빌드 최종 통과 근거는 [002 TDD 기록](tdd/002-promise-settings.md)에 있다. 이후 사용자 요청으로 003 참여·재인증·PIN 변경·로그아웃·공유 제한과 UI를 TDD로 구현했다. 정식 검토에서 발견한 로그인 탭 전환 오류를 보완하고 최종 단위 14개·DB 37개·Chromium 15개·린트·타입·빌드를 통과했다. 2026-11-14 사용자 요청으로 003을 완료 처리했다. 실행 근거는 [003 TDD 기록](tdd/003-participant-access.md)에 있다.

## 개발 방법

기존 스펙 중심 개발에 [TDD 정책](tdd-policy.md)을 적용한다. 명세의 수용 기준에 근거한 동작별 테스트를 먼저 실행하고 실패·통과 근거를 기능별로 기록한다. 001의 실제 실행 근거는 [001 TDD 기록](tdd/001-invitation-and-host.md)에 남긴다.
