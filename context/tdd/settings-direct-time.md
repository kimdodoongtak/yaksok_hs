최신 후속 검증: 승인된 최종 간격(64px 높이, 라벨 묶음 위 4px·내부 간격 3px)으로 전체 단위 56/56·DB 94/94·브라우저 125/125 및 린트·타입 검사를 통과했다. 아래는 최초 구현 당시의 기록이며 커밋·배포 보류는 최신 사용자 요청으로 해제됐다. [최종 검증 기록](settings-calendar-release.md).

2026-11-25. 기존 로컬 스타일 변경을 보존하고 새 입력 동작에 한해 Docker Node.js 24에서 집중 검증한다. 새 커밋·배포 요청은 없으며 수행하지 않는다.

실제 실행 결과를 아래에 기록한다. 이전 UI의 미검증 이력과 이번 검증을 구분한다.

- 단위 RED: `npm run test -- src/components/promise-settings/time-entry.test.ts` → exit 1, 3실패/2통과. 파싱 스텁이 유효 시각·소요 시간에 null을 반환했다.
- 단위 GREEN: 같은 명령 → exit 0, 5/5. 숫자/시각 해석, 시작·종료 자정 범위, 빈 입력·형식·30분 단위·24시간 경계를 확인했다.
- UI RED: `npm run test:browser -- promise-settings.spec.ts --grep '시간 직접 입력' --max-failures=1` → exit 1. 기존 화면에는 하루 시작 textbox가 없어 첫 동작에서 실패했다.

## 구현·회귀

- UI 연결 후 `npm run test:browser -- promise-settings.spec.ts --grep '시간 직접 입력|설정 진입 시'`: 직접 입력 2개 통과, 기존 393×700 첫 화면 노출 실패. 최근 로컬 스타일 여백 때문에 다음 버튼 하단이 787.5px이었다. 740px 이하의 짧은 모바일에서만 구역 여백을 줄이고 숫자 칸 64px·글꼴·터치 영역을 유지했다.
- `npm run test:browser -- promise-settings.spec.ts`: exit 0, 11/11 통과(25.4초). 숫자 입력 저장값, 입력 오류·다음 차단, 잘못된 값에서 화살표 복구, 실제 터치 이벤트로 포커스, 단계 왕복 보존, 기존 날짜·정원·마감·세션·반응형 회귀 포함.
- 첫 린트에서 렌더 중 ref 읽기 2건 검출. 마지막 유효값을 상태로 옮겨 조절 버튼의 비활성 상태도 함께 갱신되도록 정리했다.
- 최종 `npm run test:browser -- promise-settings.spec.ts --grep '시간 직접 입력'`: exit 0, 3/3 통과(9.1초).
- 최종 `npm run test`: exit 0, 56/56. `npm run lint`, `npm run typecheck`: 각각 exit 0.
- `docker compose exec -e INVITATION_BROWSER_TEST=1 tools npm run build`: exit 0. 로컬 개발 서버와 분리한 출력 디렉터리로 빌드했다.
- `settings-direct-time-320.png` 직접 확인: 숫자 칸·날짜·버튼·입력값 정상 표시. 이후 사용자 후속 요청으로 시작/종료 라벨과 숫자 간격만 3→7px로 늘렸다. 이 마지막 정적 간격 변경은 diff 검사만 수행했으며 브라우저를 다시 실행하지 않았다.
