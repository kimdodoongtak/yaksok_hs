# 시간 입력 코치마크 검증 기록

## 새로고침 시 안내 반복 방지 — 2026-11-25

- 사용자 피드백으로 매번 진입 시 안내하던 정책을 변경했다. 안내를 닫으면 브라우저 저장소에 기억하고 수동 사용법 재실행은 허용한다. 영구 저장소 제한 시 세션 저장소를 사용하며 양쪽 모두 제한돼도 닫기를 막지 않는다.
- RED: `npm run test:browser -- availability-coachmarks.spec.ts --grep '자동 반복.*바로 시작하기'` → exit 1. 도입을 닫고 새로고침한 뒤 dialog가 다시 visible로 나타났다.
- GREEN: `npm run test:browser -- availability-coachmarks.spec.ts` → exit 0, 16/16 통과(25.0초). 4가지 종료 방식 각각에 대해 새로고침·다른 약속 이동의 자동 표시 차단과 사용법 버튼 재실행을 검증했다. 기존 모바일 제출 후 재진입 기대값을 최신 정책에 맞춰 변경했고 터치·레이아웃 회귀도 통과했다.
- Docker Node.js 24·격리된 테스트 DB에서 실행했다. 사용자 선택 값/제출 로직은 변경하지 않았다. 커밋·푸시·배포하지 않았다. 실제 기기·저장소 차단 환경은 미검증이다.

## 도입 팝업 재확인·카드 시작선·짧은 노트북 높이 — 2026-11-25

- 사용자 스크린샷에서 도입 팝업의 아이콘/버튼 스타일 누락과 이전 데스크톱 제목/배치가 관찰됐다. 최신 코드의 새 브라우저에서는 팝업 깨짐이 재현되지 않았으므로 이를 제품 코드의 RED로 주장하지 않는다.
- RED: `npm run test:browser -- availability-coachmarks.spec.ts --grep '첫 안내|시작선'` → exit 1, 1/3 통과. 1024/1366px에서 일정 정보보다 캘린더 카드가 68px 아래에 있었고, 1024×600의 최초 완전한 시간 행은 2개였다.
- 수정: 시간 보기 탭을 캘린더 열 밖 공통 상단 줄로 옮겼다. 900px 이상에서 양쪽 카드를 같은 그리드 행에 놓고, 카드 최소 높이는 화면 하단까지 확보하며 전체 시간 행만큼 자연스럽게 늘어난다. 내부 overflow 스크롤은 만들지 않고 페이지 스크롤을 유지한다. 날짜/조작부의 한 줄 배치 기준을 1200→900px로 확장하고 짧은 노트북의 상단 여백을 줄였다.
- GREEN: 전체 관련 브라우저 11/11 통과(19.2초). 이후 900×600 경계 케이스 추가 후 도입/정렬 집중 4/4 통과(6.1초). 900/1024×600의 6개 이상 행, 1366×768, 긴 09:00~24:00 범위, 카드 시작선 오차 ≤1px, 카드 내부 스크롤 부재·실제 문서 휠 스크롤·제출부 노출을 확인했다.
- 팝업: 320/393/1024/1366px에서 버튼 높이 ≥44px·동일 너비·세로 간격 ≥8px·화면 안 배치를 확인하고 캡처를 검수했다.
- 로컬 서버: 기존 개발 프로세스만 종료하고 재생성 가능한 `.next/dev` 캐시를 지운 뒤 `npm run dev`를 재시작했다. 데이터·설정은 변경하지 않았다. 실제 시간표 경로 HTTP 200. 기존 사용자 탭의 오래된 CSS/HMR 상태 가능성을 제거하기 위한 조치이며 정확한 원인을 단정하지 않는다.
- 실제 로컬 CSS 확인: localhost:3001이 제공하는 CSS를 HTTP로 받아 격리 테스트 화면의 정적 DOM에 적용했다. 버튼 간격 8px·높이 45px·너비 272px·카드 시작선 차이 0px 확인, `test-results/live-css-welcome.png` 직접 검수. 사용자의 인증된 탭을 직접 조작한 검증과는 구분하며 개발 DB는 쓰지 않았다.
- 최종 린트·타입 검사·diff 공백 검사 및 별도 `.next-browser` 경로 빌드(`INVITATION_BROWSER_TEST=1 npm run build`) 통과. 실제 휴대전화·운영·전체 기존 E2E는 미검증이며 커밋·푸시·배포는 하지 않는다.

## 노트북 공간·안내 대상·배경 오류 수정 — 2026-11-25

- 환경: Docker Node.js v24.22.3, Chromium, 검증된 별도 `sdd_test` DB. 테스트가 생성한 링크만 정리했다. 개발 DB·운영 DB 초기화 없음.
- RED: `npm run test:browser -- availability-coachmarks.spec.ts` → exit 1, 4/5 통과. 1366×768 최초 시간표 상단 595.6875px(기준 ≤360), 폭 770px(기준 ≥850), 완전한 행 2개(기준 ≥6)로 실패했다.
- RED: 같은 명령 `--grep 1024` → exit 1. 1024×600에서 시간표 설명 대상 아래쪽이 679.6875px로 뷰포트 밖에 있었다.
- 수정: 데스크톱 제목/진행 표시의 중복 공간 축소, 최대 너비 확장, 넓은 화면의 날짜/조작부 한 줄 배치. 단계 전환 시 대상 위치를 먼저 확보하고 시간표 강조를 상단 고정부·하단 제출부 사이로 제한했다. 큰 box-shadow 방식은 전체 화면 SVG 마스크로 교체했다.
- GREEN: `npm run test:browser -- availability-coachmarks.spec.ts` → exit 0, 최종 8/8 통과(18.7초). 1366×768, 1440×900, 1024×600, 393×740, 320×640에서 5단계 대상·카드 노출/겹침·화면 경계 검사, Escape·재실행·포커스 복원, 초기 시간표 범위, 1024×900 네 모서리 배경 픽셀 비교, 모바일 터치 스크롤/선택/안내 차단/제출/재진입을 포함한다.
- 추가 회귀는 사후 검증이다. 모바일 터치 검사 첫 시도는 관성 스크롤 중 좌표가 바뀌어 실패했다. 스크롤 정지 후 다음 조작을 하도록 검사 대기를 보완했고 제품의 선택 로직은 변경하지 않았다. 반지름 12px 접촉과 칸 가장자리 입력을 포함했으나 물리적 손가락 검증으로 간주하지 않는다.
- 최종 `npm run lint`, `npm run typecheck` 각각 exit 0. `docker compose exec -e INVITATION_BROWSER_TEST=1 tools npm run build` exit 0. 빌드는 로컬 개발 서버를 유지하기 위해 별도 `.next-browser` 출력 경로를 사용했다.
- 스크린샷 직접 검수: 노트북 초기 화면은 09:00~16:00의 8개 행이 완전히 보인다. 짧은 노트북의 시간표 안내, 모바일 제출 안내를 확인했다. 산출물은 `apps/web/test-results/calendar-laptop.png`, `guide-1024-grid.png`, `guide-393-submit.png`, `guide-backdrop-1024.png`, `guide-touch-selected.png` 등 Git 제외 경로다.
- 범위 제한: 기존 전체 E2E 스위트·실제 iPhone/Android·운영 배포 검증은 하지 않았다. 커밋·푸시·배포 없음. 아래 미검증 표기는 초기 구현의 이력이다.

## 도입 화면 추가 — 2026-11-25, 미검증

- 사용자 요청에 따라 자동 안내 앞에 달력 아이콘·제목·짧은 안내와 ‘사용법 보기’/‘바로 시작하기’를 추가했다. 사용법 재실행은 기존처럼 첫 단계로 연결한다.
- 기존 모달에서 도입→5단계로 전환하며 포커스·화면 높이 처리를 공유한다. 선택 값과 제출 로직은 수정하지 않았다.
- 소스 연결만 확인했으며 테스트·린트·타입·빌드·브라우저 검수와 커밋·배포는 계속 보류한다.

2026-11-25 — 사용자 승인으로 [스펙](../features/calendar-coachmarks-spec.md)의 로컬 구현을 적용했다.

- 3단계 모달·영역 강조·건너뛰기·이전/다음·재실행·브라우저별 종료 기억을 추가했다.
- 사용자 최신 지침에 따라 테스트·린트·타입 검사·빌드·브라우저 검수는 실행하지 않았다. 실제 RED/GREEN 근거 없음. 정식 완료 상태가 아니다.
- 소스 수준에서 연결 위치와 기존 선택/제출 로직 보존을 확인했다. 이 확인은 실행 검증을 대체하지 않는다.
- 후속: 자동 노출/재노출 제한, 선택값 보존, 모달 터치/키보드 차단, 포커스 복원, 모바일 크기별 강조/카드 위치, 날짜 보기 재실행, 제출/마감 전환. 실제 휴대전화 손가락 조작 미검증.
- 커밋·푸시·배포하지 않았다.

## 같은 날 후속 UI 수정 — 미검증

- 사용자 피드백으로 5단계(선택 모드·시간표·시간 단위·주간 반복·제출)로 확장했다.
- 큰 중앙 카드 대신 240~260px 말풍선을 대상 가까이에 배치한다. 강조 영역·카드·꼬리 이동에 180ms 전환을 적용하고 reduced-motion에서는 생략한다. 버튼 높이 44px는 유지한다.
- 제출 이력과 localStorage 확인 조건을 제거해 시간표 마운트 때 자동 표시한다. 새로고침·재진입도 포함하며 같은 마운트 안에서는 종료 후 자동 반복하지 않는다.
- 스펙을 최신 동작으로 갱신했다. 테스트·린트·타입·빌드·브라우저·실기기 확인은 사용자 지침대로 실행하지 않았다. 이전의 브라우저별 종료 기억은 이번 변경으로 대체한다.
