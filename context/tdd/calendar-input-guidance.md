# 시간 입력 조작 안내 검증

> 2026-11-24 사용자 요청으로 조작 안내 UI 변경을 철회하고 관련 코드·테스트를 원복했다. 아래 내용은 시도 기록이다. 1시간 보기의 시작 시각 표시만 로컬에 유지하며 원복 후 테스트·커밋·배포는 실행하지 않았다.

- 날짜: 2026-11-24
- 스펙: [조작 안내](../features/calendar-input-guidance-spec.md)
- 시작: main, 기존 변경은 사용자 모바일 테스트 지침을 반영한 `context/coding-standards.md`뿐이다.
- TDD 대상: 단일 버튼으로 선택 시작·스크롤 복귀, 선택 보존. 정적 문구·배치는 TDD 비대상이며 회귀·화면 검수로 확인한다.
- 실제 실행 결과는 아래에 이어 기록한다.

## RED → GREEN

- `docker compose exec -T tools npm run test:browser -- e2e/availability.spec.ts -g '모바일 선택 전환으로'`: 변경 전 exit 1, `시간 선택 시작` 버튼이 없어 `toBeVisible` 실패. 구현 후 동일 테스트 1/1 통과(exit 0). 단일 버튼으로 선택 시작·복귀, 미제출 선택 보존과 다른 보기 복귀를 확인했다.
- 관련 3개 E2E 파일 첫 회귀는 60/65 통과(exit 1). 새 넓은 터치 테스트 2건, 버튼 이름 갱신 누락 1건, 보기 전환 시 스크롤 150→124 변화 1건, 이전에 제거된 되돌리기 버튼을 여전히 기대하는 재조율 테스트 1건이 실패했다.
- 넓은 접촉 면적(radiusX/Y 12) 스와이프 다음 가장자리 탭을 보내기 전에 관성 스크롤이 실제 멈추기를 기다리도록 테스트를 보완했다. 구현의 이벤트 처리나 기대값을 약화하지 않았다. 별도 탭은 접촉 반경 10과 2×1px 흔들림을 포함한다.
- 보기 전환 실패는 새 안내 높이 변화에 따른 브라우저 스크롤 앵커 보정이었다. 시간표 페이지에 `overflow-anchor: none`을 적용해 기존 스크롤 위치 유지 계약을 복구했다.
- 이름 갱신 누락을 수정하고 재조율 테스트는 현재 제품 요구사항인 되돌리기 없음, 미제출 칸 해제, 기존 저장 칸 3개 보존을 검증하도록 고쳤다.
- 영향 테스트 `-g '친절한 조작|주와 보기 전환|전체 시간과 참여자|모바일 선택 전환으로'`: 5/5 통과(exit 0). 추가 터치 시나리오는 기존 동작의 사후 검증이며 새로운 RED→GREEN으로 주장하지 않는다.

## 검수

- 320·393px 터치 화면과 1280px 마우스 화면을 캡처해 확인했다. 선택 단위·안내·버튼 겹침 없음, 모바일 주요 조작 높이 44px, 기존 첫 화면 네 행 유지. 마우스에서는 직접 선택 안내만 보인다.
- `npm run test`: 51/51 통과(exit 0). 최초 린트 통과. 최종 회귀·린트·타입·빌드 결과는 아래에 기록한다.
- 실제 휴대전화·iPhone Safari·카카오톡 WebView의 손가락 조작은 미검증이다. 에뮬레이션 접촉 면적 설정으로 실기기 검증을 대체하지 않는다.

| 수용 기준 | 확인 근거 | 남은 작업 |

| AC3 입력 수단·모드별 안내 | 터치·마우스 미디어 조건, 날짜 안내와 읽기 전용 확인 | 없음 |

새 서버 동작·DB 변경·외부 호출·의존성 추가는 없다. 친구들 시간 겹쳐 보기와 시간 칸 높이는 범위에 넣지 않았다. 기존 모바일 검증 지침 문서는 사용자 요청으로 앞서 추가된 변경으로 보존한다.

## 사용자 요청으로 검증 보류

2026-11-24 사용자가 로컬에서 빠르게 확인하는 흐름을 우선하며 테스트·커밋·배포를 나중에 진행하도록 변경했다. 진행 중이던 최종 브라우저 회귀의 중단을 시도하는 동안 실행이 종료되어 최종 65/65 통과(exit 0)를 수신했다. 이후 추가 테스트는 실행하지 않았다. 단위 51개·보완 집중 5개·최종 린트는 중단 요청 전에 통과했다. 최종 타입 검사·빌드는 실행하지 않았고 커밋·푸시·배포도 수행하지 않았다. Docker Node.js v24.22.3. 개발 서버는 유지하며 상태는 로컬 적용·사용자 확인 중이다.
