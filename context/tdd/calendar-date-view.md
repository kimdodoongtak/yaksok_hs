## 실제 RED → GREEN

1. `npm run test -- src/components/availability/date-selection.test.ts` (모두 Docker): 원본 선택을 반환하는 스텁에서 필요한 2슬롯 누락으로 exit 1 → 날짜 채우기·해제 구현 후 1/1, exit 0.
2. 같은 명령으로 현재 경계·지난 시간 보존 테스트 추가: 현재 시각 슬롯이 추가되어 exit 1 → 미래 필터와 약속 날짜 범위 검사 후 2/2, exit 0.
3. 하루 인원 집계 테스트: 0명 스텁이 기대 전체 1/일부 2와 달라 exit 1 → 참여자별 슬롯 수 교집합 구현 후 3/3, exit 0.
4. `npm run test:browser -- e2e/availability.spec.ts --grep '날짜 보기에서 하루'`: 날짜 버튼 미존재로 exit 1 → 날짜 카드 구현. 첫 재실행은 오늘 안내가 같은 문장에 합쳐져 exact 문구 조회 실패. 안내 span 분리 후 1/1, exit 0. 날짜 전체·일부·해제, 시간 조정, 주 이동, 두 날짜 36슬롯 저장과 재조회 확인.

## 회귀 계획

- 기존 2시간 보기 높이 전용 테스트 1개 제거: 입력 단위 자체가 제품에서 제거됨. 혼합 선택·마지막 짧은 칸 검증은 1시간과 23:30 종료로 대체, 히트맵 구간 중앙 검증은 1시간으로 유지.
- 날짜 카드 터치 탭/스와이프, 읽기 전용 인원 요약, 제출 실패/초기화/마감은 추가 흐름 회귀로 확인한다.

5. 날짜 요약 브라우저 테스트: 첫 실행은 테스트 fixture의 하루 범위보다 긴 소요 시간으로 DB 제약 실패(유효 RED 아님). fixture 수정 후 조회 실패인데 카드에 ‘조회 중’이 남는 실제 RED(exit 1)를 확인하고 오류 상태 전달로 보완했다.
