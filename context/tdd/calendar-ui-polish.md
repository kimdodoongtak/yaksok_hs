# 시간표 UI 전체 검증·배포 기록

2026-11-25 사용자가 전체 테스트/검사 후 커밋·푸시·배포를 요청했다. 로컬 보류 지침을 이번 변경 범위에서 해제한다. 기존 로컬 변경을 모두 최종 검토하며 새 브랜치는 만들지 않는다.

## 범위

- [최종 UI 스펙](../features/calendar-ui-polish-spec.md), [안내 스펙](../features/calendar-coachmarks-spec.md). 최초 단일 버튼 시안은 철회된 이력이며 배포 기능으로 간주하지 않는다.
- 시작 HEAD `cf7bbdb`, main과 origin/main 동일. 앱/문서 변경은 이번 세션의 사용자 요청 범위다.
- 검증 환경: Docker Node.js v24.22.3, 실제 격리 `sdd_test`, Chromium. 운영 DB를 테스트에 사용하지 않는다.

## 실행 기록

- `npm run test`: exit 0, 단위 51/51.
- `npm run test:integration`: exit 0, 실제 DB 94/94, 기존 5개 마이그레이션 적용 상태 확인.
- 첫 `npm run lint`: exit 0.
- 첫 브라우저 전체 회귀는 `--max-failures=2`로 실행해 안내 16개 통과 후 기존 시간 입력 2개가 첫 방문 모달에 막히는 것을 확인했다. 신규 사용자 흐름은 별도 안내 테스트가 담당하고, 기존 도메인 회귀는 실제 브라우저의 안내 종료 기록을 가진 재방문 사용자 fixture로 보완했다. 테스트를 건너뛰거나 제품에 테스트 전용 우회를 추가하지 않았다.
- 시간 칸 높이(44→36px), 마감/후보 버튼의 상단 공통 줄 이동과 비대칭 메뉴/마감 열에 맞춰 기존 화면 검사를 갱신했다. 시간표 중앙·버튼 간 겹침·행 수 검사는 유지한다.

## 전체 회귀에서 발견한 문제

- 두 번째 전체 브라우저 실행: 117/122 통과, exit 1.
- 실제 UI RED: 집계 조회 실패 시 재시도 버튼이 도움말 행을 4px 늘려 모바일 문서 스크롤과 데스크톱 시간표 위치가 바뀌었다. 도움말 내부를 flex 정렬하고 버튼 높이를 기존 행의 28px에 맞췄다. 기존 위치 비교 조건은 완화하지 않았다.
- 날짜 터치 테스트는 관성 스크롤이 끝나기 전에 다음 탭을 실행했다. 실제 스크롤 정지를 기다린 후 다음 동작을 하도록 보완했다.
- 메뉴의 제거된 브랜드 링크 대신 일정 제목·초대/참여 정보 링크를 검사하고, 재조율은 제거된 되돌리기 버튼 대신 미제출 선택 취소와 기존 저장 3개 슬롯 보존을 검사한다.
- 집중 GREEN: `npm run test:browser -- --grep '모바일 날짜 탭|모바일 상단 정보를|주 전환 조회|모집 중 확대 저장'` → exit 0, 5/5 통과.
- 최종 전체 `npm run test:browser`: exit 0, 122/122 통과(4.2분), 건너뛴 테스트 없음.
- 최종 `npm run lint`, `npm run typecheck`, `npm run db:validate`: 각각 exit 0.
- `docker compose exec -e INVITATION_BROWSER_TEST=1 tools npm run build`: exit 0. 로컬 서버를 유지하고 별도 `.next-browser` 출력 경로에서 운영 빌드 성공.
- `git diff --check`: exit 0. 캡처 `calendar-laptop.png`, `welcome-320.png`, `guide-1024-grid.png` 직접 확인: 일정/캘린더 시작선, 첫 화면 시간 행, 팝업 버튼 간격과 안내 대상 노출 정상.

실제 휴대전화와 저장소 접근 차단 환경은 미검증이다. Chromium 터치 에뮬레이션을 물리적 손가락 테스트로 표현하지 않는다. 초기 UI 구현 후 추가한 검사는 사후 회귀이며, 실제 RED→GREEN은 위 위치 밀림과 별도 코치마크 기록의 재현된 오류에 한정한다.

서버 인증·인가·DB 스키마·의존성 변경 없음. 신규 클라이언트에는 안내 표시 상태와 브라우저 저장소 키만 추가하며 비밀값은 포함하지 않는다. 기존 인증·소유권·동시성 검사는 실제 격리 DB에서 통과했다. 원격 main과 시작 HEAD가 동일하며 범위 밖 사용자 파일은 없다.

## 커밋·배포 인계

구현·검토·검증 완료. 사용자 요청에 따라 main에 커밋·푸시하고 GitHub 연동 Vercel 운영 배포를 확인한다. 프로젝트 `yaksok-hs`의 main 운영 연결을 CLI로 확인했다. 배포 SHA·READY·운영 HTTP 응답은 푸시 후 실제 결과로 최종 보고하며, 이 기록 시점에는 새 배포 성공을 주장하지 않는다. 운영 DB에 테스트 쓰기나 스키마 변경은 수행하지 않는다.
