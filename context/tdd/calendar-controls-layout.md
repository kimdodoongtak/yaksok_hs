# TDD 실행 기록: calendar-controls-layout

- 스펙: [시간표 조작 영역](../features/calendar-controls-layout-spec.md)
- 시작점: main `3d9cf9e`, 작업 트리 깨끗함.
- 상태: 구현·검증 완료
- 사용자 최신 지침: 검증 후 커밋·푸시. 방장 마감은 상단 오른쪽.
- 경계: 격리 PostgreSQL fixture와 Playwright Chromium. 서버 계산·스키마 변경 없음.

## 검증 계획

- 주간 반복 → 초기화 진입, 빈 주에서 전체 초기화: 새 동작 RED→GREEN.
- 초기화 범위·지난 시간·취소·외부 갱신·반복·제출: 기존 동작 회귀.
- 상단 메뉴/중앙 탭, 모드와 시간 단위 한 줄, 제출 옆 타이머/상단 오른쪽 방장 마감: 배치 검사·실제 화면 검수. 정적 스타일은 TDD 비대상.
- 되돌리기/복구는 사용자 요청으로 제거한다. 관련 전용 테스트를 제거하는 이유를 아래에 명시하고 남는 제품 동작의 검증은 보존한다.

## 실제 RED → GREEN

- `docker compose exec -T tools npm run test:browser -- --grep '주간 반복 안에서 빈 주'`
- RED: 기존 footer에 초기화가 남아 있어 count 0 기대에 실제 1, exit 1.
- GREEN: 주간 반복 내부 진입과 빈 주 전체 초기화 구현 후 동일 테스트 1개 통과, exit 0. 초기화 후 제출 전 DB 보존 및 제출 후 삭제 확인.
- 제거한 전용 테스트 3개는 되돌리기·복구와 화살표 도움말 동작에만 해당한다. 혼합 테스트의 반복·초기화 범위·지난 시간·미제출 데이터 보존은 유지했다.
- 중간 회귀 50개 중 45개 통과, 5개 실패: 기존 메뉴 글자/탭 전체 폭 가정 3개, 마감 후 반복 disabled 기대값 수정 오류 1개, 화면 확보로 줄어든 최대 스크롤보다 큰 이동량 기대 1개. 새 배치와 실제 스크롤 한계에 맞게 검증을 수정했다.
- 두 번째 회귀: 48/50 통과. 2개 초기화 진입 테스트는 Next 개발 배지가 주간 반복 클릭을 가로채며 시간 초과했다. 기존 반복 테스트처럼 실제 배지 닫기 버튼을 누르는 공통 도움 함수를 적용했다. 제품 이벤트를 강제로 호출하거나 테스트 기대를 완화하지 않았다.

## 최종 검증

- `docker compose exec -T tools npm run test:browser -- e2e/availability.spec.ts e2e/candidates.spec.ts`: 48/50 통과 후 위 개발 배지 원인 보완.
- `docker compose exec -T tools npm run test:browser -- e2e/availability.spec.ts --grep '초기화|주간 반복|짧은 모바일|모바일 선택 전환'`: 실패 2개 포함 영향 범위 11/11 통과, exit 0. 나머지 48개는 앞 실행의 통과 근거를 유지하며 최종 전체 재실행으로 표기하지 않는다.
- Docker Node.js 24 `npm run test`: 단위 46개 통과. `npm run lint`, `npm run typecheck`, `npm run build`: 모두 exit 0. 최종 린트 경고 없음.
- 320·393px 캡처에서 상단 메뉴·중앙 탭·오른쪽 방장 마감, 하단 주간 반복·남은 시간·선택 제출을 확인했다. 320px 주간 반복 창의 초기화 진입·스크롤 범위도 검수했다. 1280px 배치 및 마감 후 후보 이동은 브라우저 테스트로 확인했다.
- 사용하지 않는 EditButton과 되돌리기 전용 스타일·이력만 제거했다. 터치 선택·기본 스크롤·PC 마우스/키보드, 지난 시간·다른 주·서버 갱신·마감 권한은 유지했다.
- 실제 휴대전화 Safari·카카오 WebView 사용감은 미검증이며 사용자 모바일 확인 대상이다. 운영 DB 쓰기나 정책 변경 없음.
- 사용자 요청으로 main 커밋·푸시한다. 최종 SHA·배포 상태는 Git 및 해당 커밋의 Vercel 배포 결과를 따른다.
