# TDD·테스트 관련 토큰 사용량 분류

집계일: 2026-11-17. 범위: 프로젝트 개발 시작부터 **2026-11-15 13:21:17 KST의 009 완료 커밋 시점**까지. 이전에 보고한 337,701,586개와 동일한 범위이며, 이후 디자인·운영 작업과 이번 분석은 포함하지 않는다.

## 결과

**테스트 직접 관련으로 분류한 응답은 65,777,715개(19.48%)다.** 제품 구현과 섞인 응답 및 검증 기록 작성까지 더하면 211,826,691개(62.73%)지만, 이를 전부 TDD 비용 또는 TDD 때문에 증가한 토큰이라고 해석할 수 없다.

| 응답 분류 | 캐시 포함 전체 토큰 | 전체 비율 | 캐시 제외 입력 + 출력 |
| --- | ---: | ---: | ---: |
| 테스트 직접 관련 | 65,777,715 | 19.48% | 2,326,963 |
| 테스트 + 제품 코드·다른 검사 혼합 | 119,885,758 | 35.50% | 3,037,374 |
| TDD·검증 기록 작성 관련 | 26,163,218 | 7.75% | 294,674 |
| 그 외 린트·타입·빌드 검사 관련 | 23,426,409 | 6.94% | 448,873 |
| 나머지·미분류 | 102,448,486 | 30.34% | 4,888,550 |
| **합계** | **337,701,586** | **100%** | **10,996,434** |

비율은 반올림으로 합이 100%와 약간 다를 수 있다. 캐시는 입력에 포함되므로 다시 더하지 않으며, 추론 토큰도 출력에 포함되므로 중복 가산하지 않는다. 캐시 제외 열은 일반 입력과 출력의 합이지 과금액이나 새로 생성한 글의 양이 아니다.

### 개발 응답과 자동 승인 검토 구분

기존 집계에서 ‘보조 세션’으로 합산한 51,023,888개는 이번 로그 확인 결과 **guardian 자동 승인 검토 세션**이다. 다른 개발 에이전트가 병렬로 기능을 구현한 비용이라고 해석하지 않는다.

| 분류 | 주 개발 응답 | 자동 승인 검토 |
| --- | ---: | ---: |
| 테스트 직접 관련 | 41,331,298 | 24,446,417 |
| 테스트 혼합 | 119,388,352 | 497,406 |
| 검증 기록 관련 | 26,163,218 | 0 |
| 다른 품질 검사 | 13,811,836 | 9,614,573 |
| 나머지·미분류 | 85,982,994 | 16,465,492 |
| **합계** | **286,677,698** | **51,023,888** |

자동 승인 검토도 로컬 사용량 카운터에 기록되어 기존 총량과 일치하도록 포함했다. 구독 사용량 차감 또는 청구 여부를 확인한 것은 아니다.

## 집계 방법

1. 로컬 Codex 세션의 `session_meta.cwd`가 이 프로젝트 루트와 정확히 일치하는 파일을 읽었다. 과거 대화 복제본에 반복 등장하는 `event_msg.token_count`를 제거했다.
2. 주 개발 대화는 누적 입력·캐시·출력·추론·전체 카운터 조합으로 전역 중복 제거하고, 자동 승인 검토는 세션별로 중복 제거했다. 원래 집계와 동일하게 종료 시각의 해당 초 전체를 포함했다.
3. 사용량이 있는 주 대화 11개와 승인 검토 세션 31개에서 **중복 제거된 사용량 이벤트 2,790개**를 얻었다. 이벤트가 없는 세션과 종료 시점 이후에만 사용량이 있는 세션은 합계에 기여하지 않는다.
4. 각 사용량 이벤트를 `token_usage_record`와 대응시켜, 그 응답에서 실제 요청한 도구 작업과 바로 앞 도구 결과를 분류했다. 응답별 입력·출력 전체를 해당 분류에 배정했으며, 응답 안의 토큰을 임의 비율로 나누지 않았다.
5. 테스트 파일 수정·읽기, 테스트 명령 실행 및 프로세스 결과 확인을 테스트 관련으로 표시했다. 같은 배치에 제품 코드 읽기·수정 또는 린트·타입·빌드가 있으면 혼합으로 분리했다. 배치에서 시작된 대기 프로세스는 그 배치의 분류를 계승한다.
6. `context/tdd/` 등의 검증 기록 작성은 별도 분류했다. 이 분류에는 다른 문서 수정과 검사가 같이 있는 응답도 포함한다. 그중 52개 응답, 7,231,949개 토큰은 제품 코드 또는 다른 검사도 함께 표시되어 있다.
7. 승인 검토는 전체 상속 대화를 검색하지 않고 **실제 승인 요청의 예정 명령**만 분류했다. 일반 지침이나 문서 속 `TDD`, `RED`, `GREEN`, `npm run test` 언급만으로 테스트 작업에 넣지 않았다.
8. 개별 기록과 대응되지 않은 승인 사용량 이벤트 1개(38,257개)는 미분류에 남겼다.

## 해석의 한계

- **순수 TDD와 사후·회귀 테스트를 완전히 분리한 집계가 아니다.** 실제 RED/GREEN 증거는 기능별 `context/tdd/`에 있지만, 모든 모델 응답에 TDD 단계 라벨이 기록되어 있지는 않다.
- **TDD를 하지 않았으면 절약했을 토큰을 계산한 것이 아니다.** 혼합 응답에는 TDD가 없어도 필요한 제품 구현이 들어 있고, 사후 테스트도 별도 비용이 든다. 비교 실행이 없으므로 순증분과 절감 가능 비율은 알 수 없다.
- 테스트 관련 응답도 기존 대화·지침·코드 전체를 입력으로 포함한다. 따라서 65,777,715개가 모두 테스트 문장이나 코드였다는 뜻은 아니다.
- 테스트 명령을 실행한 도구 자체가 토큰을 발생시키는 것은 아니다. 명령을 생성하고 결과를 받아 다음 작업을 판단한 모델 응답의 사용량을 센 것이다.
- 정적 명령·명시적 파일 경로 기반의 재현 가능한 분류다. 동적 스크립트, 임시 수동 검사, 테스트 사이의 구현 추론 등은 기타 또는 미분류에 남을 수 있다. 직접 관련 수치 역시 TDD 비용의 엄밀한 하한은 아니다.
- API 금액이나 실제 구독 청구액으로 해석하지 않는다.

## 검증 및 재현

- 기존 [개발 집계](development-metrics.json)의 전체·입력·캐시·출력·비캐시 입력 등 **6개 비교 항목이 모두 정확히 일치**했다.
- 모든 행에서 `전체 = 입력 + 출력`, `캐시 ≤ 입력`을 확인했다. 직접 관련 분류에는 제품 읽기·수정·다른 품질 검사 표시가 없음을 확인했다.
- 응답별 출처 파일·행 번호·사용량·분류 근거는 [CSV](tdd-token-usage-events.csv), 요약과 한계는 [JSON](tdd-token-usage.json)에 남겼다. 대화 본문, 비공개 추론, 원시 도구 명령·출력, 인증 정보는 내보내지 않았다.
- 재현: 프로젝트 루트에서 `python3 apps/web/scripts/analyze-tdd-usage.py`. 로컬 `~/.codex/sessions`를 읽고 원래 집계와 일치하는지 검증한 뒤 `/tmp/yaksok-tdd-usage-rows.json`과 `/tmp/yaksok-tdd-usage-summary.json`을 만든다. 원본 세션 로그가 있어야 실행할 수 있다.
- 이는 저장된 로그의 통계 분석이다. 앱 코드·DB·개발 서버를 변경하거나 제품 테스트를 재실행하지 않았다. 커밋·푸시·Notion 기록도 수행하지 않았다.
