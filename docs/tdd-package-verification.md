# TDD 작업폴더 검증

검증일: 2026-11-03

이 문서는 이번 TDD 작업폴더의 정적 검증 결과다. 원본 작성자의 환경 검증과 구분한다.

## 확인 범위

- 스킬 5개의 YAML 메타데이터와 실제 디렉터리 구조
- Markdown 내부 파일 링크와 TDD 정책 참조
- 구현·검토·테스트·완료 단계의 TDD 연결과 비대상 처리
- 원본 앱 설정·패키지·잠금 파일·DB 스키마·Dockerfile의 바이트 동일성과 두 배포본의 Compose 이름·포트 분리
- 배포 ZIP 무결성, 압축 해제 후 내용 동일성, 심볼릭 링크·경로 문자열 진입점 없음
- Claude용과 Codex용의 스택·TDD 정책 동일성

## 실행하지 않은 검증

- 현재 실행 환경에 Docker가 없어 `docker compose`, `npm ci`, Prisma·앱 빌드를 실행하지 않았다.
- 앱·제품 테스트가 아직 없어 제품 동작, 실제 DB 통합 테스트, 브라우저 UI는 미검증이다.
- 실제 Claude Code/Codex 클라이언트에서 스킬 자동 발견을 실행 확인하지 않았다. 각 도구의 표준 프로젝트 스킬 디렉터리 구조로 구성했다.
- 이 지침은 TDD 작업 순서를 안내한다. 에이전트가 실제 프로젝트에서 이를 수행했는지는 기능별 실행 로그와 리뷰로 확인해야 한다.

패키지 구조 검사 결과는 같은 폴더의 `package-checks.json`에 기록한다.
